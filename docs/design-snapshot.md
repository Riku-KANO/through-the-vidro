## 概要
丸い吹きガラスでできた街を、手にしたガラス玉を覗きながら彷徨い、失われた光と色を取り戻す。Webブラウザで遊べる、一人用の一人称3D探索パズルです。
**一言ピッチ**: ガラス玉を覗くと、見えなかった道が見える。

| 項目 | 内容 |
|---|---|
| ジャンル | 一人称の探索パズル(散策＋軽い謎解き) |
| プレイ時間 | 本編 約70分(序章5分＋3エリア各15〜20分＋終章10分) |
| 人数 | 1人 |
| プラットフォーム | PCブラウザ(Chrome / Edge / Firefox / Safari の最新版)。タブレット(タッチ操作)は公開後のアップデートで対応 |
| 入力 | マウス＋キーボードとゲームパッドに公開時から対応。タッチは公開後のアップデートで対応 |
| 公開 | Cloudflareで静的配信。サーバーなし、セーブはブラウザ内 |
| ターゲット | 雰囲気のある探索ゲームが好きな人。パズルが苦手でも最後まで行ける難度 |
| 言語 | 日本語と英語。公開時から両方に対応 |

### 体験の核
1. **透明な空間を歩く心地よさ**: 光が透け、床に虹色の模様が落ちる街をただ歩くだけで楽しい
2. **覗いた瞬間の発見**: 行き止まりに見えた場所に、玉越しにだけ橋が架かっている
3. **色が戻る達成感**: 無色透明だった街が、琥珀・瑠璃・翡翠と少しずつ色づいていく

### 設計の柱
すべての判断はこの4本に照らして決めます。
1. **ガラスは飾りではなく仕組み**: 透ける・屈折する・転がる・鳴るという性質を、そのまま遊びのルールにする
2. **迷わずに彷徨える**: 行き先に迷う楽しさは残し、どこを歩けるか分からないストレスは消す
3. **画面と世界の境目がないUI**: UIもガラスで作り、ホーム画面からゲーム世界まで1カットでつなぐ
4. **どの瞬間を切り取っても一枚絵になる**: 光・構図・色の設計を全カットで妥協しない

## 世界観とストーリー
舞台は、職人たちが吹いたガラスだけで築いた街「ハリノ」です。中央の灯塔(ともしびのとう)の大玉が割れて光が散り、街は色を失いました。プレイヤーは大玉のかけらである一つのビードロを手に、散った光を集めて街を元に戻します。

### 街の成り立ち
- 建物はすべて吹きガラスの泡の集まりで、角のある形は一つもない
- 中央の灯塔の頂には大きなガラス玉があり、太陽の光を集めて街じゅうに配っていた
- 光は建物から建物へ屈折して届き、住人はその光で暮らしていた

### 光が失われた理由
- ある朝、灯塔の大玉が割れ、光は無数の「光の雫」になって街に散った
- 光の通り道がずれたことで、住人や橋や扉は消えたのではなく、少しずれた「裏の層」に取り残された
- 表の層に残ったのは、無色透明で静まり返った街だけ

### 主人公
- 名前も姿も持たない一人称の存在。街外れの工房で目を覚ます
- 作業台に一つだけ残っていたビードロ(大玉のかけら)を手にする。この玉だけが、ずれた裏の層を映せる

### 語り口
- 台詞や音声はほぼ使わない。物語は景色と光と音で語る
- 住人の言葉は「残響」として裏の層のガラスに残っている。覗くと、曇りガラスを指でなぞったような短い一文が浮かんで消える(各エリア5つ、計15)
- 寂しさではなく、見つける喜びを基調にする。住人は助けを待つ被害者ではなく、まだそこで暮らしている気配として描く

### 結末
1. 集めた光の雫を灯塔に運び、主人公自身が新しい大玉を吹く(吹きガラスの短い操作)
2. 新しい大玉が光を集め、色の波が街全体へ広がる。裏の層の住人や橋が表に重なって見え始める
3. カメラが引いていくと、街全体が一つの大きなビードロの中にあったことが分かる
4. その玉はホーム画面のガラス玉と同じ構図で止まり、タイトルへ戻る。クリア後のホーム画面の玉の中は、色を取り戻した街になっている

## コアメカニクス
遊びの中心は、手のガラス玉で「覗く」と「置く」の2つです。覗くと裏の層が見え、置くとその周りだけ裏の層が実体化します。置いている間は覗けないことが、すべてのパズルの緊張を生みます。
（図の内容）1 彷徨う → 2 違和感に気づく(行き止まり、空の台座、光の揺らぎ) → 3 覗く(玉越しに裏の層の橋や光の雫が見える) → 4 置く・転がす・鳴らす(裏の層を実体化) → 5 道が開き、雫を得る → 次の部屋へ(1へ)。雫が3つ揃うと 6 色が戻る(玉に新しい性質) → 次のエリアへ。序章と3エリアで計10周。
部屋から部屋へ移る周回では色は戻らず、エリアの3つ目の雫で初めて街に色が差します。

### 基本の動作

| 動作 | 効果 | 制約 |
|---|---|---|
| 歩く | 街を一人称で移動する。段差は自動で上る | 落下死はない。足場の縁ではやわらかく止まる |
| 覗く | 手の玉が視界中央にせり上がり、玉越しの円の中だけ裏の層が屈折して見える | 覗いている間は移動速度50%。玉を置いているときは覗けない |
| 置く | 台座(玉座)に玉を置くと、玉を中心とした球の中が裏の層に置き換わる | 台座にしか置けない。置いている間は手ぶら |
| 拾う | 置いた玉を回収し、実体化を解く | 実体化した足場の上にいるときは回収できない(玉が小さく震えて知らせる。光で定着した足場の上では回収できる) |
| 調べる | 残響や光の雫に触れる | なし |

### 裏の層のルール
- 街は同じ場所に重なった2つの層でできている。表は今の無色の街、裏は光があった頃の街の名残
- 裏にだけあるもの: 橋、階段、扉、住人の残響、光の雫
- 表にだけあるもの: 崩れた壁、割れた破片の山、閉ざされた扉
- 玉を置くと、その球の中では裏が表を置き換える。裏の橋が現れて渡れるようになり、表にしかない壁は消えて通れるようになる
- 実体化の範囲は半径4m(主玉)。範囲の境目は光の膜として見え、外へは踏み出せない
- 光の雫は裏の層にしかない。覗いて見つけ、置いて実体化させてから触れて回収する

### ガラス玉の性質の成長
エリアをクリアして色が戻るたびに、玉に新しい性質が加わります。新しい動作を増やすのではなく、同じ玉でできることが広がる設計です。

| 獲得時期 | 色 | 性質 | 何ができるか |
|---|---|---|---|
| 序章 | 無色 | 覗く・置く | 基本の2動作 |
| エリア1クリア | 琥珀 | 転がる | 斜面や溝に玉を転がし、手の届かない台座へ送る。丸い玉ならではの動き |
| エリア2で入手 | ― | 小玉 | 覗けないが置ける小さな玉(実体化半径2m)。最大2個持てる |
| エリア2クリア | 瑠璃 | 鳴る | 玉を指で弾くと音が鳴る。同じ音程のガラス器が共鳴し、数秒だけ周囲の裏の層が浮かび上がる |
| エリア3クリア | 翡翠 | 光を曲げる | 玉を通した光の筋が曲がり、離れた場所へ光を届ける。終章で使う |
小玉が入ることで、「道を小玉で保ったまま、主玉を持って先を覗く」という2手先を読む遊びが生まれます。

## 進行構造とエリア設計
中央広場と灯塔を中心に、3つのエリアが放射状に広がる構造です。エリアは1→2→3の順に開くので迷いませんが、灯塔は常に見えているため、一本道ではなく街を巡っている感覚が残ります。

| 順 | エリア | 景観と時間帯 | 主に使う性質 | 雫 | 戻る色 | 目安 |
|---|---|---|---|---|---|---|
| 0 | 序章「工房」 | 街外れの吹きガラス工房。夜明け前の青 | 覗く・置く(チュートリアル) | 1 | ― | 5分 |
| 1 | 泡の工房街 | 泡が連なる住居群と坂道。朝 | 覗く・置く | 3 | 琥珀 | 15分 |
| 2 | 雫の水路 | 雫形の塔とガラスの水路。雨の昼 | 転がる・小玉 | 3 | 瑠璃 | 20分 |
| 3 | 鐘の温室 | 巨大なドーム温室とガラスの植物。夕方 | 鳴る・小玉 | 3 | 翡翠 | 20分 |
| 4 | 終章「灯塔」 | 街の中心の塔。夜から夜明け | 全性質＋光を曲げる | ― | すべて | 10分 |

### エリアの内部構造
- 1エリア = 入口の広場＋3つの「雫の部屋」＋帰り道の近道
- 雫の部屋は1部屋に1つのアイデア。3部屋目は前の2部屋の組み合わせ
- 3つ目の雫を得ると、入口の広場への近道が実体化して戻れる(帰り道の作業をなくす)
- 中央広場へ戻ると色の波の演出が入り、次のエリアの門が開く

### 街の配置と序章の締め（2026-10-23 決定。詳しくは ハリノの地図 設計案 https://claude.ai/artifact/PXGzajkiZcwjWiDRBCsZuQ）
- エリアを方角に置き、日の動きと同じ時計回りに一日が進む：序章の工房は北東の丘（夜明け前）、エリア1は東（朝）、エリア2は南（雨の昼）、エリア3は西（夕方）、終章は中央の灯塔
- 街は直径およそ 300m。中央広場は半径約 25m、各エリアの入口の広場まで約 60m、1エリアは約 80×80m。中央広場の時間帯は直前に終えたエリアの時間を引き継ぐ
- 序章の締め：光の雫を取ると、裏の橋が表に定着し（玉を拾っても消えない）、向こう岸の門が開く。橋を戻って玉を拾い、門から約 80m の坂道を下って中央広場へ。広場では東のエリア1の門だけが開いている。定着は、雫が入った玉から光が橋を渡り（約 1.6 秒）、光が通った所から裏の橋が表に定着する。光が向こう岸に届くと門が開く（解けた理由が光と音で見える）。定着した橋は裏の層の虹色のまま
- エリア1の部屋：入口の広場から東へ坂を上り、坂の下「崩れた壁の路地」（表だけの壁を単独で）、中ほど「二つの台座の中庭」（二重の台座＋表だけの壁）、頂「煙突の見晴らし」（置くと先が見えない）。3つ目の雫で頂から入口の広場への裏の階段が表に定着して近道になる（序章の橋と同じ見せ方）。部屋の中身は作って遊んでから詰める

### 色が戻る進行
- 色は特定のエリアだけでなく、街全体に戻る。エリア1を終えると、まだ行っていないエリア2・3の建物にも琥珀の色が差す
- これにより、プレイヤーは中央広場から遠くを見るたびに自分の進捗を景色で確認できる。進捗バーは置かない
- 色ガラスは厚い部分ほど濃く見えるため、同じ琥珀でも建物ごとに表情が変わる

### やり込み要素
- 残響(住人の言葉)を各エリア5つ、計15。ホーム画面の「残響」から読み返せる
- 全部集めると、エンディング後に住人たちの姿が表の層に加わった「光の戻った街」を自由に散策できる

## パズル設計
答えは常に「覗けば見える」場所に置き、総当たりではなく観察で解けるパズルにします。難しさは操作の正確さではなく、玉をどこに置くかの順序から生まれるようにします。

### 原則
1. **観察で解ける**: 必要な情報はすべて画面に出ている。隠し要素探しで詰まらせない
2. **1部屋1アイデア**: 新しいギミックは「安全な場所で単独」→「別の要素と組み合わせ」→「ひねり」の3段階で出す
3. **罰がない**: 落下・死亡・やり直しはない。玉を拾えばいつでも元の状態に戻る
4. **解けた理由が分かる**: 解けた瞬間に、なぜそうなったかが光と音で見える
5. **一部屋の目安は3〜5分**: それ以上かかる場合はヒントの段階を早める

### ギミック一覧

| ギミック | 初出 | 内容 | 使い方の例 |
|---|---|---|---|
| 台座(玉座) | 序章 | 玉を置ける場所 | 置く位置の選択肢そのもの |
| 裏の橋・階段 | 序章 | 覗くと見え、実体化すると渡れる足場 | 行き止まりの先へ進む |
| 表だけの壁 | エリア1 | 表の層にしかない壁や破片の山 | 置いて消し、通り抜ける |
| 二重の台座 | エリア1 | 範囲が重なる位置にある2つの台座 | どちらに置くかで開く道が変わる |
| 斜面と溝 | エリア2 | 玉を転がす経路 | 手の届かない台座へ玉を送る |
| 水流 | エリア2 | 水路の流れが玉を運ぶ | 流れの分岐を実体化で切り替える |
| 小玉 | エリア2 | 覗けないが置ける玉 | 道を保ちながら主玉で先を覗く |
| 共鳴器 | エリア3 | 音程を持つガラスの器や鐘 | 玉を鳴らし、同じ音の器の周りの裏を一時的に見る |
| 音階の扉 | エリア3 | 決まった音の並びで開く扉 | 共鳴器を順に鳴らす |
| 光の筋 | 終章 | 灯塔へ向かう光の通り道 | 玉で光を曲げ、塔の頂へ集める |

### 難易度の曲線
- 序章: 失敗のしようがない一本道で「覗く→置く→渡る」を体で覚える
- エリア1: 置く場所の選択。最後の部屋で初めて「置くと先が見えない」問題に向き合う
- エリア2: 転がす・小玉で手数が増える。2手先を読む部屋が出てくる
- エリア3: 音で見るという別の感覚が加わる。視覚に頼らない解き方への切り替えが山場
- 終章: 新しいルールは1つだけ(光を曲げる)。難しさより、これまでの全要素を使う気持ちよさを優先する

### ヒント設計
1. **環境の誘導(常時)**: 空気中の光の粒が、注目すべき方向へゆっくり流れる
2. **玉のささやき(1分停滞)**: 手の玉がかすかに鳴り、注目すべき台座や裏の気配が一瞬だけ光る
3. **残響のヒント(任意)**: ポーズメニューの「ヒント」で、住人の言葉として一文の手がかりが浮かぶ
ヒントは設定でオフにできます。停滞の判定は「同じ部屋で新しい行動が起きていない時間」で測ります。

## 空間の可読性と導線
透明な街では「どこが壁で、どこを歩けるか」が分からなくなりやすく、これを放置すると彷徨う楽しさが迷子のストレスに変わります。以下の9つのルールを、全エリアのレベルデザインとアート制作の必須条件にします。

### 歩ける場所を読ませる
1. **歩ける面は透明にしない**: 床と道は曇りガラス・石畳・真鍮の格子。透明なのは壁・建物・装飾だけ。透明な床は、エリア3の空中回廊の1か所だけを見せ場として使い、縁を光らせる
2. **形は縁で伝える**: 視線に対して斜めの面ほど強く反射する性質(フレネル)で輪郭を浮かせる。断面の縁には本物のガラスと同じわずかな緑を入れる
3. **床の光で上の形を読ませる**: ガラスを通った光の模様(コースティクス)を床に落とし、見上げなくても頭上の形が分かるようにする
4. **当たり判定は見た目に正直に**: 見えている曲面にそのまま沿って歩ける。丸い壁に沿って滑らかに流れ、角で引っかからない

### 行き先を示す
5. **常に見える目印**: 灯塔は街のどこからでも見える。各エリアにも固有の目印を置く(工房街の煙突、水路の雫塔、温室のドーム)
6. **透明だから遠くが見える**: 次に行く場所がガラス越しに先に見えている構図を、各部屋の入口に必ず作る
7. **光の粒の流れ**: 空気中の塵が光の中で漂い、進むべき方向へ少しだけ流れる

### 画面をうるさくしない
8. **奥ほど霞ませる**: 透明な物が何枚も重なると画面が煩雑になる。距離に応じて霞(大気遠近)を強め、遠景のガラスは単純な表現に切り替える
9. **行き止まりには必ず理由を置く**: 台座か、裏の層の気配(光の揺らぎ)のどちらかが必ずある。理由のない行き止まりは作らない

### ミニマップは置かない
画面上の地図は彷徨う楽しさを壊すため置きません。代わりに、ポーズ中に「地図の玉」(街の縮図が入ったガラス玉)を手のひらで回して見られるようにし、現在地と見つけた雫だけを光らせます。

## 操作とカメラ
操作は一人称の標準に合わせ、覚えることを「歩く・覗く・置く」の3つに絞ります。すべてのキーは設定で割り当て直せます。

### 入力の割り当て

| 動作 | キーボード＋マウス | ゲームパッド | タッチ(公開後に対応) |
|---|---|---|---|
| 移動 | W A S D | 左スティック | 画面左側の仮想スティック |
| 視点 | マウス | 右スティック | 画面右側のドラッグ |
| 覗く | 右クリック長押し | LT長押し | 右下の玉ボタン長押し |
| 置く・拾う・調べる | 左クリック または E | A | 対象をタップ |
| 鳴らす(エリア3から) | 覗きながら左クリック | 覗きながらRT | 覗きながら玉ボタンをタップ |
| 小玉を切り替える | ホイール または 1〜3 | 十字キー左右 | 玉ボタンを左右にスワイプ |
| 早歩き | Shift | 左スティック押し込み | 仮想スティックを外側まで倒す |
| ポーズ | Esc | Start | 画面右上の小さな雫 |
- 覗く操作は「長押し」と「押すたびに切り替え」を設定で選べる
- マウスはPointer Lock(ブラウザのマウス固定)を使う。初回はクリックで固定し、Escで解除する

### カメラ
- 一人称、目の高さ1.6m、視野角70度(設定で60〜100度)
- 加速と減速に短い慣性をつけ、ガラスの街を滑るように歩ける手触りにする。歩行速度は1.4m/s、早歩きは2.2m/s
- 歩行時の上下の揺れはごく弱く、設定でオフにできる
- 覗いている間は視野角をわずかに狭め(-6度)、玉に集中している感覚を出す
- 演出でカメラを動かすときは、必ず入力を一時的に預かり、終わったら元の向きへ自然に戻す

### 3D酔い対策
- モーションブラーは使わない
- 視野角、歩行の揺れ、覗いたときの歪みの強さを設定で調整できる
- 画面中央の小さな点(視点の基準)を表示できる
- 演出の強いカメラ移動は、設定で短い版に置き換えられる

## UI/UX設計
UIはすべてガラスで作り、画面に貼りついた板ではなく、世界の中にある物として見せます。ゲーム中の常時表示はゼロを基本にし、必要な情報は手のガラス玉や景色そのものに持たせます。

### UIの原則
1. **世界の中に置く**: 情報は手の玉・景色・光で伝える。画面に固定する表示は最後の手段
2. **素材はガラスだけ**: 曇りガラス、透明ガラス、雫、指でなぞった文字の4つで全画面を構成する
3. **すぐ応える**: 入力から0.1秒以内に必ず音と動きで反応する。重い処理の前でも先に手応えを返す
4. **色は進行と同期する**: UIのアクセント色も、街に戻った色(琥珀→瑠璃→翡翠)に合わせて変わる
5. **読みやすさは雰囲気より優先**: どの背景の上でも文字が読めるよう、文字の背後は必ず曇らせる

### 文字と色
- 本文と見出しは細めの明朝体(候補: Shippori Mincho、Zen Old Mincho)。数字と英字は細身のサンセリフ
- 文字色は白に近い温かい灰色。背景の曇りガラスは白10〜18%の濃さに背後のぼかしを合わせる
- 最小の文字サイズは1080p基準で18px。字幕は24px以上
- フォントは使う文字だけに絞ったサブセットを作り、容量を抑える

### 英語版
- 言語の初期値はブラウザの言語設定で決め、ホーム画面の設定からいつでも切り替えられる
- 英語の書体は、明朝体の細さと品に合わせた細めのセリフ体(候補: Cormorant Garamond、EB Garamond)
- 英語は日本語より横に長くなりやすい(1.5〜2倍)。曇りガラスの札や雫のボタンは、文字の長さに合わせて伸びる作りにする
- 「指でなぞった文字」は書き順ではなく、文の左から右へ光の筆跡が進む表現にして、日本語と英語で同じ仕組みにする
- 翻訳の範囲は、UI、残響15本、ヒント約30本、クレジット。残響は直訳せず、英語で詩として読める文に書き起こす

### 画面ごとの設計

| 画面 | 見た目と動き | 操作 |
|---|---|---|
| 読み込み | 白い霧の中に小さなガラスの器があり、読み込みに合わせて光で満ちていく。満ちたら「はじめる」が浮かぶ | クリックで開始(ブラウザは操作があるまで音を鳴らせないため、ここで一度押してもらう) |
| ホーム | 中央に大きなガラス玉。中には街の縮図が実際の3Dで入っていて、屈折して見える。マウスに合わせて玉がわずかに傾き、中の光が流れる。項目は玉の周りに浮かぶ小さな雫 | 雫にホバーすると膨らんで鳴る。項目は「はじめる / つづきから / 残響 / 設定 / クレジット」 |
| ゲーム中 | 常時表示なし。調べられる物に近づくと縁が淡く光り、画面下に曇りガラスの小さな操作表示が出る(例: E 置く)。0.2秒で現れ、離れると消える | ― |
| 光の雫の数 | 手の玉の中に光の粒として入っていく。覗くと玉の中で粒が漂っているのが見える | 数字は出さない。ポーズ中の地図の玉で確認できる |
| 残響(字幕) | 画面中央下に曇りが広がり、指でなぞるように一文が書かれ、数秒で晴れて消える | 読み終えたら左クリックで早送り |
| ポーズ | 時間が0.4秒かけてゆっくり止まり、息を吹きかけたような曇りが中心から広がる。項目は曇りの上に指でなぞった文字として書かれる | 「つづける / ヒント / 地図の玉 / 設定 / タイトルへ」 |
| 地図の玉 | ポーズ中に、街の縮図が入った玉を手のひらで回して眺める。現在地と見つけた雫が光る | ドラッグで回転、ホイールで拡大 |
| 設定 | 曇りガラスのパネルが横に広がる。タブは画質 / 操作 / 音 / 表示とアクセシビリティ | 変更は即時反映。パネル越しに見える景色で結果を確かめられる |
| 残響の棚 | ガラス板が並ぶ棚。集めた残響の板だけが光り、選ぶとその文が浮かぶ | 未発見の板は輪郭だけ見える |
| エンディング | カメラが引き、街が玉の中にあったと分かる。玉がホーム画面と同じ位置で止まり、そのままタイトルに戻る | スキップ不可(初回のみ)。2回目以降は長押しでスキップ |

### 細部の振る舞い
- **ホバーと選択**: 雫は近づくと表面張力で少し膨らみ、選ぶと弾けずに沈み込む。選択中の項目は、内部に光が灯る
- **キーボード・パッド操作**: マウスなしでもすべての画面を操作できる。フォーカス中の雫は光と音で分かる
- **戻る操作**: どの画面でもEsc / Bで一つ前に戻れる。戻るときは、来たときの動きを逆再生する
- **確認ダイアログ**: 「タイトルへ戻る」など取り消せない操作だけ確認する。確認は曇りガラスに2択の文字を書く形
- **セーブの通知**: 自動セーブ時は、画面の隅ではなく手の玉が一瞬だけ温かく光る

### アクセシビリティ
- 字幕と文字の大きさを3段階で変更できる
- コントラスト強化モード: ガラスの縁を太く明るくし、曇りガラスの背景を濃くする
- 色だけに頼らない: パズルに必要な情報は形と音でも伝える。共鳴は光の輪として目にも見える
- 音の手がかりはすべて視覚化できる(音の方向を画面の縁の光で示す)
- 光の点滅や強い閃光を抑えるモード
- 覗くの長押し/切り替え、キーの割り当て変更、ヒントのオン/オフ

## トランジション設計
すべての遷移は「ガラス越しに次の場面が見えてくる」という一つのルールで統一し、黒い画面での切り替えは使いません。読み込み待ちも遷移の演出の中に隠します。
（図: 読み込み→ホーム→ゲーム⇄ポーズ、ホーム/ポーズ→設定、ゲーム→エンディング→ホーム。演出は下の遷移の一覧）
設定パネルはホーム画面とポーズの両方から開き、どちらでも背後の景色が見えたまま操作できます。

### 遷移の一覧

| 遷移 | 演出 | 長さ | 実装の方式 |
|---|---|---|---|
| 読み込み → ホーム | 器が光で満ちて溢れ、霧が晴れ、奥からガラス玉が浮かび上がる | 1.5秒 | 霧はフルスクリーンのシェーダ。玉は最初から同じシーンにあり、霧の濃さだけを動かす |
| ホーム → ゲーム開始 | カメラが玉へ近づき、表面を通り抜ける瞬間に屈折の歪みが画面いっぱいに広がって、そのまま工房の中に立っている | 2.0秒 | 玉の中身は序章のシーンそのもの。玉越しに描いていた映像を、画面全体の描画へ連続的に切り替える |
| ホーム → つづきから | 玉の中の街の該当エリアへ寄ってから潜る | 2.5秒 | 同上。寄る先をセーブ位置で決める |
| 覗く開始・終了 | 玉が視界の下からせり上がり、玉越しの円が広がる。終了は逆再生 | 0.25秒 | 玉の位置と屈折の強さを補間する |
| 玉を置く(実体化) | 玉から光の波紋が球状に広がり、波面が通過した所から裏の層に置き換わる | 0.8秒 | 実体化の半径を0から4mへ動かし、境目を光らせる |
| ゲーム → ポーズ | 時間がゆっくり止まり、曇りが中心から広がり、文字が書かれる | 0.4秒＋文字0.3秒 | 止まった画面を一枚の画像に写し、曇りと文字のシェーダをかける |
| ポーズ → ゲーム | 曇りが外側から晴れ、時間が動き出す | 0.3秒 | 上の逆 |
| エリア間の移動 | 雫が画面の上から流れ落ち、雫越しに次のエリアが映って、雫が通り過ぎると移動が終わっている | 1.2秒 | 次のエリアを事前に裏で読み込み、雫の形の歪みで2つの画面を合成する |
| 色が戻る | 灯塔から色の波が街全体へ広がっていく | 約10秒 | 色の境目を距離で進める。2回目以降は短縮版 |
| 設定パネル | 曇りガラスが横に広がり、閉じると縮んで消える | 0.3秒 | 画面上の要素(DOM)のアニメーション |
| エンディング → ホーム | 街が玉の中だったと分かるまで引き、ホームの玉と同じ構図で止まる | 約20秒 | ホームの玉と同じカメラ位置へつなぎ、切れ目を作らない |

### 遷移のルール
1. **黒い画面を使わない**: ただし設定の「簡易トランジション」では、0.3秒の白いフェードに置き換えられる
2. **待ち時間を演出の中に隠す**: 次の場面の読み込みは前もって始め、演出の長さの中で終わらせる。間に合わないときは演出の途中の姿勢で止め、完了したら続きを再生する
3. **短く、2回目は速く**: 1秒を超える演出は、2回目以降に短縮版を使う
4. **入力を奪いすぎない**: 0.5秒を超える演出の間も、Escだけは常に受け付ける
5. **動きの曲線を揃える**: ガラスらしい、ゆっくり始まって粘りながら止まる曲線を全画面で共通にする
6. **音を必ず添える**: 遷移ごとに固有のガラスの音を割り当て、目を閉じていても何が起きたか分かるようにする

## アートディレクション
キーワードは「静けさ」「温度のある透明」「朝の光」です。角のない曲面のガラスと、細い真鍮の枠の対比で街を組み立て、色は進行とともに少しずつ増やします。

### ガラスの種類

| 種類 | 見た目 | 使う場所 | 材質の方向性 |
|---|---|---|---|
| 透明ガラス | 無色。断面の縁がわずかに緑 | 建物の外殻、橋、ドーム | 屈折率1.5、粗さ0、厚みは場所ごとにムラをつける |
| 曇りガラス | すりガラスの柔らかい拡散 | 床、道、UIのパネル | 粗さ0.4〜0.6、透過は残す |
| 色ガラス | 琥珀・瑠璃・翡翠。厚い所ほど濃い | 進行で解放される建物、窓 | 色は表面ではなく内部の吸収で出す |
| 気泡入りガラス | 内部に細かな泡が浮かぶ | 手の玉、装飾、近景の小物 | 泡は内部の別の小さな形状として入れる |
| 虹色ガラス | シャボン玉のような干渉の虹 | 裏の層の物、光の雫 | 薄膜干渉(イリデッセンス)を使う |
| 乳白ガラス | 光を内部で散らす半透明 | 街灯、灯りの器 | 透過を抑え、内側から発光させる |

### 形のルール
- 角を作らない。すべて曲面で、ベベル(面取り)の半径は大きめにとる
- 直線と細い線は真鍮の枠だけに許す。枠がガラスの形を引き締め、透明な物の輪郭を補う
- 建物は泡の集合として作る。大小の泡が溶け合ったような形で、同じ形の繰り返しに見せない

### 色の進行

| 時点 | パレット |
|---|---|
| 序章〜エリア1 | ほぼ無色。白、薄い青灰、ガラスの縁の緑、真鍮の鈍い金 |
| エリア1クリア後 | 琥珀が加わる。光も暖かくなる |
| エリア2クリア後 | 瑠璃が加わる。影の部分に青が差す |
| エリア3クリア後 | 翡翠が加わる。植物と水が生き返ったように見える |
| 終章の後 | 全色と、白金色の暖かい光 |

### 光と時間帯
- エリアごとに時間帯を固定する: 序章は夜明け前の青、エリア1は朝、エリア2は雨の昼、エリア3は夕方、終章は夜から夜明け
- 光源は太陽1灯＋空からの環境光が基本。静止した光と影はBlenderで焼き込み、動く物だけを実時間で照らす
- 反射用の環境マップは、外部の写真ではなく街の中からBlenderで撮った360度画像を使い、ガラスに街そのものが映るようにする

### 画面の仕上げ
- ブルーム(光のにじみ)は控えめにし、強い光源と光の雫だけが滲む
- 色収差(虹色のずれ)は普段は使わず、覗いている玉越しにだけ強くかける
- ハイライトが白く飛びにくいトーンマッピング(AgX)を使い、ガラスの強い反射でも色を残す
- 被写界深度は覗いている間だけ使い、玉の外側を少しぼかす

## サウンドデザイン
音はこのゲームのもう一つの主役です。街のすべてのガラスは鳴り、その音はすべて同じ音階に揃えるため、どこで何を鳴らしても濁らず、歩くだけで小さな音楽が生まれます。

### 音階の統一
- 全体をDメジャーのペンタトニック(5音)に揃える。環境音、ガラスの音、UIの音、楽曲のすべてが対象
- 5音だけの音階は、どの組み合わせで重なっても不協和音になりにくい
- メニューの雫は上から順に音が上がるように割り当て、操作するだけで短い旋律になる

### ガラスの音
- 大きい物ほど低く、小さい物ほど高く鳴る(物理的に自然な対応)
- 触れる・叩く・玉が当たるの3種類の強さを用意する
- 手の玉は、長崎のビードロ(ぽっぺん)のような「ぽぺん」という音を持つ。覗く・置く・拾うのたびに鳴る、このゲームを代表する音
- 共鳴器は5音分を用意し、音を鳴らすと同時に光の輪を広げて目にも見せる

### 環境音
- 風がガラスの隙間を抜ける音、遠くの風鈴、水滴、雨がガラスを打つ音
- 足音は床の材質ごとに変える(石畳、曇りガラス、真鍮の格子)。各8種類をランダムに使う
- 空間の広さに合わせて残響を変える。狭い工房は短く、温室のドームは長く
- 音は3D空間に配置し、ヘッドホンでは方向が分かる立体音響(HRTF)を使う

### 音楽
- 作曲した楽曲は使わない。音楽は、録音したガラスの音を音階に沿ってプログラムで組み合わせる「生成音楽」で作る。短い旋律の断片(4〜8音)を規則に沿って選ぶので、毎回少しずつ違う演奏になる
- 光の雫を拾うたびに、そのエリアの生成音楽の層(低い持続音、ゆっくりした分散和音、高いきらめき)が1つずつ重なる。3つ揃うと完成した響きになる
- 旋律が前に出るのは、色が戻る演出、エンディング、ホーム画面の3か所だけ
- この3か所は、余力があればSunoで生成した曲に置き換える。使わない場合は、生成音楽の層をすべて重ねた特別版で成立させる

### 制作方法
- ワイングラス、ガラス瓶、風鈴、ガラスの器を実際に録音し、音程を揃えて、生成音楽と効果音の両方の素材にする
- 生成音楽の規則(音の選び方、間合い、層の重ね方)はClaudeが実装し、調整用のパネルで聴きながら詰める
- 足りない音はシンセサイザーで補う
- ブラウザの互換性のため、圧縮形式を2種類用意する
- 音量は「全体 / 音楽 / 効果音 / 環境音」を別々に調整できる

### Sunoを使う場合
- 対象はホーム画面、色が戻る演出、エンディングの3曲
- プロンプトでDメジャー、ゆったりしたテンポ、グラスハープやチェレスタ中心の編成を指定する。キーがずれた曲は音程を調整して生成音楽と合わせる
- 2026年9月3日からのSunoの規約では、商用の権利は有料プランでSunoからダウンロードした曲にだけ付き、無料プランの曲は個人の非商用利用に限られる。広く公開する作品なので、有料プランで生成・ダウンロードする
- Proプランのダウンロードは月20曲まで。生成は多めに行い、ダウンロードは採用する曲だけにする
- Sunoのリミックス機能で作った曲は商用利用できないため使わない
- ダウンロード時のプランと日付を記録して曲のファイルと一緒に保存し、公開前に最新の規約を確認する
参考: [Sunoのダウンロード上限と商用の権利(Mubertによる解説、2026年10月20日更新)](https://mubert.com/blog/suno-download-caps)

## 技術設計
Three.jsのWebGPUレンダラー(WebGPU非対応の環境では自動でWebGL2に切り替わる)を土台にします。最大の技術課題は「ガラス越しのガラス」と「裏の層の二重描画」の2つで、どちらも設計段階で描画コストを制御します。

### 技術スタック

| 領域 | 採用 | 理由 |
|---|---|---|
| 言語・ビルド | TypeScript ＋ Vite | 型で状態管理の事故を防ぎ、開発中の再読み込みが速い |
| 3D描画 | Three.js(WebGPURenderer) | WebGPUが使えない環境では自動でWebGL2へ切り替わる。独自シェーダはTSL(Three.jsのシェーダ言語)で書けば両方で動く |
| ガラスの材質 | MeshPhysicalMaterial(ノード版) | 透過・屈折率・厚み・色の吸収・分散・薄膜干渉を標準で持つ |
| 物理 | Rapier(WebAssembly) | 一人称の移動(キャラクター制御)と玉が転がる剛体を一つのエンジンで扱える |
| UI | DOM＋TypeScript、動きはGSAP | 文字の鮮明さ、キーボード操作、読み上げ対応はDOMが有利 |
| 音 | Web Audio API | 立体音響(HRTF)と空間ごとの残響を直接扱える |
| アセット圧縮 | glTF ＋ meshopt ＋ KTX2 | 形状とテクスチャを小さくし、読み込みとGPUメモリを抑える |
| 配信 | Cloudflare(静的配信) | サーバー不要。アセットは長期キャッシュ |
WebGPUレンダラーの採用は決定済みです。M0では、WebGPUを使えない環境で自動的に使われるWebGL2の経路でも、ガラスの品質と速度が許容範囲に収まるかを確かめます。

### 1フレームの描画の流れ
1. 不透明な物(床、真鍮の枠、台座、焼き込み済みの背景)を描く
2. 遠景のガラスを、透過を使わない安価な表現(環境マップの反射＋霞)で描く
3. 近景の透過ガラスを描く。背後の画像は1と2の結果を使う
4. 覗いている場合だけ、裏の層を低解像度の別画像に描く
5. 手の玉を専用シェーダで描く。表の画像と裏の画像を、玉の屈折に沿って合成する
6. 仕上げ(ブルーム、玉越しの色収差、トーンマッピング、アンチエイリアス)
7. UIの曇りや雫の効果を重ね、最後にDOMのUIを上に表示する

### ガラスの描画
- 材質は透過(transmission)1.0、屈折率1.5、厚みは厚みマップで場所ごとに変える。色ガラスは内部の吸収色で色を出し、厚い所ほど濃く見せる
- **最大の制約**: 標準の透過は、背後の不透明な物しか映さない。ガラスの奥にある別のガラスは映らない
- 対策1(レベルデザイン): 主要な視線の上で「透過ガラスの奥に透過ガラス」が重ならない配置にする。重なる場所は遠景側を安価な表現に切り替える
- 対策2(描画の工夫): 見せ場の数か所だけ、ガラスを含めた画面を先に別画像へ描き、それを手前のガラスが参照する(1パス増える)
- 対策3(手の玉): 手の玉は常に専用の合成で描くため、この制約を受けない
- 分散(虹色のにじみ)と薄膜干渉は描画が重いので、手の玉・光の雫・見せ場に限って使う

### 裏の層の実装
- **層の分け方**: 表の物と裏の物を別のグループに分け、描画対象を切り替えられるようにする
- **覗く**: 覗いている間だけ、同じカメラで裏の層を画面の0.5〜0.75倍の解像度で別画像に描く。手の玉のシェーダが、玉の表面の向きから屈折した位置を計算してその画像を読む
- **実体化**: 置かれた玉の位置と半径(最大3つ: 主玉＋小玉2)を全材質に渡す。表の物は球の内側を、裏の物は球の外側を描かない。境目は光る縁として描く
- **当たり判定**: 裏の足場は細かい区画に分けておき、実体化の球と重なる区画だけ当たり判定を有効にする。球の縁には見えない柵を置き、外へは歩き出せないようにする
- **安全**: 玉を拾う前に、プレイヤーが裏の足場の上にいないかを判定する

## Blenderアセットパイプライン
Blenderは造形だけでなく、光の焼き込み・厚みマップ・反射用の環境画像・ゲーム用の情報の埋め込みまで担います。手作業は造形と見た目の判断に集中させ、それ以外はPythonスクリプトで一括処理します。

### 流れ
1. **造形**: 丸いガラスの形を作る
2. **厚みと材質**: ガラスの厚みを作り、材質をglTFに書き出せる形で設定する
3. **ゲーム情報の付与**: 台座、層、音程などをオブジェクトのカスタムプロパティに書く
4. **焼き込み**: 光と影、光の模様、厚みマップ、反射用の環境画像を作る
5. **書き出しと圧縮**: glTF(.glb)で書き出し、形状とテクスチャを圧縮する
6. **確認**: ブラウザの確認用ページで見た目と性能を確かめる

### 造形
- **基本の丸み**: 粗い形を作り、サブディビジョンサーフェスで丸める。角はベベルで大きく面取りする
- **泡の集合(建物)**: ジオメトリノードで大小の球を配置し、ボリュームに変換してからメッシュに戻すと、泡が溶け合った形になる。その後リメッシュと削減でポリゴン数を整える
- **雫・ドーム**: カーブを回転させた形をベースにし、ジオメトリノードの数値でバリエーションを量産する
- **真鍮の枠**: ガラスの面からカーブを抽出し、細い管として作る
- **法線**: スムーズシェードに統一し、面取り部分は加重法線で整える。ガラスは法線の乱れがそのまま歪みとして見えるため、ここは特に丁寧に確認する

### 厚みと材質
- **近景の重要物**(手の玉、台座の周り): ソリッド化で内側と外側の2枚の面を持たせ、本物の厚みを作る
- **それ以外**: 1枚の面のまま、厚みマップで厚みを表現する(法線を反転させてAOを焼くと、厚みの分布が得られる)
- 材質はプリンシプルBSDFで作る。透過、屈折率、粗さを設定し、色ガラスの色はボリューム吸収ノードで設定する(glTFの吸収色・吸収距離として書き出される)
- 厚みマップは、glTF用の出力ノード(glTF Material Output)の厚みの入力につなぐ
- 分散や薄膜干渉のようにBlenderから書き出せない設定は、命名規則で印をつけ、読み込み時にコード側で設定する（※Blender 5.2 は分散・薄膜干渉も glTF に書き出せる。分散は品質プリセットで切り替えるため、印からコード側で設定する作りは変えない。S-23）

### 命名規則とゲーム情報

| 対象 | 名前の例 | 意味 |
|---|---|---|
| 表の層の物 | A1_bld_dome03_front | エリア1、建物、ドーム3番、表 |
| 裏の層の物 | A1_brg_bridge02_back | エリア1、橋2番、裏 |
| 当たり判定 | A1_bld_dome03_col | 見た目とは別の簡単な形 |
| 台座 | A1_sock_02 | カスタムプロパティに実体化半径を持つ |
| 共鳴器 | A3_bell_D4 | カスタムプロパティに音程を持つ |
| 詳細度違い | _LOD0 / _LOD1 / _LOD2 | 距離で切り替える |
カスタムプロパティはglTFのextrasとして書き出し、ゲーム側で読み取ってギミックを自動で組み立てます。

### 焼き込み
- **光と影(ライトマップ)**: 不透明な物(床、枠、台座)に2つ目のUVを作り、Cyclesで間接光込みの陰影を焼く
- **光の模様(コースティクス)**: ガラスを通った光が床に落とす模様をCyclesで描き、床のテクスチャに焼き込む。焼き込みで出にくい場合は、真上からの正射影レンダリングで模様だけを出して投影する
- **反射用の環境画像**: 各エリアの数か所から360度のパノラマをCyclesでレンダリングし、ガラスに映る景色として使う
- **時間帯**: ライトマップはエリアの時間帯で1種類だけ焼く。色が戻る前後の差は、焼き込みではなくゲーム側の色の調整で表す

### 書き出しと圧縮
- glTF 2.0(.glb)で書き出す。透過、屈折率、吸収(ボリューム)、スペキュラーの各拡張を含める
- 書き出し後、gltf-transformで形状をmeshopt圧縮、テクスチャをKTX2に変換する(法線マップは高品質方式、色は高圧縮方式)
- エリアごとに1ファイル＋共通アセット1ファイルに分ける

### ポリゴンとテクスチャの予算

| 種別 | 三角形数の目安 | テクスチャ |
|---|---|---|
| 手の玉 | 8,000 | 1024px |
| 近景の建物1棟 | 20,000〜40,000 | 2048px(ライトマップは共有) |
| 遠景の建物 | 2,000〜5,000 | 512px |
| 小物 | 500〜3,000 | アトラスで共有 |
| 1エリア全体 | 100万以下 | 合計80MB以下(GPU上) |

### 自動化
- Blenderを画面なしで起動してPythonスクリプトを実行する形で、次を一括処理する: 命名規則の検査、ポリゴン数の報告、2つ目のUVの生成、焼き込み、書き出し、圧縮
- ローカルのBlenderを使える環境であれば、モデリングの下ごしらえから書き出しまでをClaudeがスクリプトで進め、見た目の最終判断だけを人が行う分担にできる

## リスクと対策
最も大きいリスクは描画の重さと、透明な空間での迷子です。どちらも技術検証(M0)と垂直スライス(M1)の段階で実機とテストプレイで確かめ、早めに設計を直します。

| リスク | 起きると何が困るか | 対策 | 確認する時期 |
|---|---|---|---|
| ガラスの描画が重く、内蔵GPUで60fpsが出ない | 推奨環境で遊べない | 遠景の安価な表現、背景画像の解像度（※three r186 では効かない。S-10）、品質プリセット、動的解像度。M0で最も重い場面を先に作って測る | M0 |
| ガラス越しのガラスが映らず、見た目が破綻する | 見せ場の品質が落ちる | 重なりを避ける配置ルール、見せ場だけの追加パス | M0〜M1 |
| 透明な空間でプレイヤーが迷う | 彷徨う楽しさがストレスに変わる | 可読性の9ルール、テストプレイで迷った場所と時間を記録する | M1 |
| 覗く操作が疲れる、酔う | 長く遊べない | 長押しと切り替えの選択、歪みの強さの設定、覗く場面の頻度の調整 | M1 |
| パズルが難しすぎる、簡単すぎる | 途中でやめる、印象に残らない | 3段階のヒント、部屋ごとの所要時間の計測 | M1〜M2 |
| Blenderでのアセット制作が想定より多い | 予定が遅れる | モジュール化、ジオメトリノードでの量産、スクリプトでの自動化 | M2 |
| ブラウザごとの差(特にSafari、WebGPUの有無) | 一部の環境で表示が崩れる | WebGL2への自動切り替えを前提に、両方の経路で毎週確認する | 全期間 |
| 音が自動再生されない | 最初の体験が無音になる | 読み込み画面で必ず一度クリックしてもらう設計 | M1 |
| 読み込みが長い | 最初の1分で離脱される | 初回15MB以下、エリアごとの分割と先読み | M1 |
| 作りたいものが膨らみ続ける | いつまでも完成しない | 判断記録に「やらないこと」を書き、追加は次の作品へ回す | 全期間 |
| Sunoの規約や提供の形が変わる | 予定していた3曲が使えなくなる | 生成音楽だけで成立する設計を基本にし、Sunoの曲は差し替え可能な追加として扱う | M3 |

### やらないこと
- 戦闘、時間制限、落下死
- オンライン機能、ランキング
- 画面上の地図、クエスト一覧
- 音声による台詞

## 判断記録と未決事項
未決事項の判断は原則としてこの文書で決めて記録し、変える場合は理由とともに書き換えます。
姉妹作である案2の設計書は @泡沫回廊 企画・設計書 です。共通の部品と、2作品を作る順番の提案はそちらにまとめています。

### 決めたこと

| 判断 | 内容 | 理由 |
|---|---|---|
| 視点 | 一人称 | 手の玉を覗く体験と、空間に包まれる感覚を最優先するため |
| 失敗の扱い | 落下死・やり直しなし | 彷徨う心地よさを壊さないため |
| 地図 | 画面上の地図なし、ポーズ中の地図の玉のみ | 迷う楽しさを残すため |
| 描画 | Three.jsのWebGPUレンダラー(WebGL2へ自動切替) | 確定。将来性があり、WebGPU非対応の環境もWebGL2で動くため |
| 物理 | Rapier | 移動と転がる玉を一つで扱える |
| 音階 | Dメジャー・ペンタトニック | どの音が重なっても濁らないため |
| 公開 | Cloudflareで静的配信 | サーバー不要で運用が軽い |
| 案2との関係 | ガラスの材質、UIの曇り表現、音の仕組み、Blenderの自動化を共通部品にし、別々のディレクトリにそれぞれ同じものを置く | 2作品の制作量を減らし、品質を揃えるため |
| タイトル | 「ビードロの向こう」で確定 | ガラス玉を覗くという作品の核を、そのまま表すため |
| 入力の優先度 | マウス＋キーボードとゲームパッドは公開時に対応。タッチは公開後のアップデート | ゲームパッドは一人称の標準的な操作で対応が軽い。タッチは視点操作と「覗く」の長押しに別の設計が要り、タブレットではガラスの描画も重いため、公開時の品質をPCに集中させる |
| 言語 | 日本語と英語を公開時から | 台詞がほぼなく翻訳量が少ないため、最初から海外の遊び手にも届けられる |
| 音楽 | 作曲はしない。ガラスの音による生成音楽を基本に、余力があればSunoで3曲 | 作曲者がいなくても完成させ、Sunoの曲は後から足せる形にするため |
| 進め方 | 案2と並行。別々のディレクトリで開発し、M0の技術検証は2作品で共通 | 共通の部品を一度で作り、2作品で同時に磨くため |
