# スライスを1つ進める

引数: スライスID（例 `S-02`）。作業ディレクトリはこのリポジトリのルート（worktree でもよい）。

## 0. 準備

1. `AGENTS.md`、`process/loop.md`、`process/spine.yaml` の該当スライス、`process/slices/<ID>.md`（なければ作る）を読む。
2. スライスの `requirements` に書かれた設計書の節を `docs/design-snapshot.md` で読む。数値は必ず設計書から取る。
3. `git status` と `git log --oneline -5` で、ブランチが `slice/<ID>-...` であること、他人の未コミット差分がないことを確かめる。
   main の checkout にいる場合は機能を編集せず、worktree を用意してから始める。
4. `pnpm install` が済んでいなければ実行する。`scripts/check.sh` が緑で始まることを確認する。

## 1. 受け入れ条件 → テスト（赤）

1. spine の `acceptance` を、確かめ方つきで記録ファイルに書き写す（単体テスト / ブラウザセンサー / スクリーンショット / 人の判断）。
2. 純粋なロジックは `src/<area>/*.test.ts` に振る舞いのテストを書く。
3. 動きの検証は `tests/e2e/<ID>-*.spec.ts` に書く。シーンは `window.__vidro.sceneProbe` に状態を出し、
   テストはキー入力やマウス操作を送ってその値を確かめる（`tests/e2e/scenes.spec.ts` を参考に）。
4. テストを実行し、**未実装が理由で**落ちることを確認する。落ち方を記録ファイルの「赤の証跡」に残す。

## 2. 実装 → 緑

1. `paths` の範囲だけを編集する。範囲外の変更が必要なら、記録ファイルに提案を書いて止める。
2. 実装の試行回数を記録ファイルに書いてから始める（累計3回まで）。
3. `SCENES=<自分のシーン> scripts/check.sh --full` が `ALL OK` になるまで直す。
   WebGPU と WebGL2 の両方で緑であること。

## 3. 見る

1. `artifacts/screens/<scene>.png` と `<scene>-webgl.png` を Read で開いて見る。
2. 設計書の見た目の条件（アートディレクション、空間の可読性の9ルール、画面の仕上げ）と照らす。
   食い違いがあれば直して2に戻る（3巡まで）。
3. 動きの確認が要るときは、`pnpm dev` を起動して内蔵ブラウザで開くか、`?demo=1` などの台本つきモードで
   複数の時点のスクリーンショットを撮るテストを足す。

## 4. レビュー

1. reviewer エージェント（`.claude/agents/reviewer.md`）に、スライスID、差分（`git diff main...HEAD`）、
   スクリーンショットのパス、設計書の該当節を渡す。
2. P1（壊れている・設計と違う）と P2（性能予算・両経路・保守性の問題）を直す。直したら2の検査を再実行する。2巡まで。

## 5. 記録してコミット

1. `process/slices/<ID>.md` を更新する: 状態（red/green/reviewed）、検査結果、計測値の表（`node scripts/bench-report.mjs`）、
   見た目の確認結果、残件、判断待ち、AGENTS.md への提案。
2. `src/core/` を変えたら `src/core/CHANGELOG.md` に追記する（案2へのコピー対象になるため）。
3. 自分のブランチにコミットする。メッセージは `S-0X: <要約>`。main へのマージ・push はしない。

## 6. 報告して止まる

最後のメッセージに次を書く: ブランチ名、状態、受け入れ条件ごとの結果、計測値、スクリーンショットのパス、
判断待ちの事項。次のスライスは自分で始めない。
