## 結論

- **three r186 では、透過の背景画像を縮小して写せない。**
  - 背景画像は1回の描画につき1度、最初の透過物の直前に、描画先と同じ大きさで 1:1 に写される。
  - 写したあとミップが作られる。
  - 公開の API には、縮小して写す口も、読む段を制限する口もない。
- **読み出しの段を下げる近似は、作って測ったが採らない。**
  - 作ったのは「背景画像の低いミップから読む」近似。読む段に下限を付けた（低は2段＝1/4、中は1段＝1/2）。
  - 静かな状態の実機ベンチ（Apple M5 Pro）で、効果は WebGPU の低で約 0.02ms（約2%）だけだった。ほかは誤差の範囲。
  - 見た目の代償は低で大きく、効果に見合わない（下の「レビューの指摘」）。
- **r186 で背景画像の解像度を実際に変える手段は、描画解像度（`renderScale`）と動的解像度だけ。**
  背景画像は描画先と同じ大きさで写されるので、描画解像度を下げれば背景画像も同じだけ小さくなる。
- `QUALITY_PRESETS.transmissionScale` は設計の値として残す。`src/core/quality.ts` に「r186 では効かない（S-10）」とコメントした。
  0.3.0 の既知の制約（`transmissionScale` は効かない）は、そのまま有効。
- 品質の係数（COST_FACTOR）は変えない。静かに測り直した比は S-05 とほぼ同じだった（下の「計測」）。

## 調べた three r186 の実装の要点

- **透過の読み出し**
  - 透過（`MeshPhysicalNodeMaterial` の transmission）は、`PhysicalLightingModel.start()` の中で `getIBLVolumeRefraction` を組む
    （`src/nodes/functions/PhysicalLightingModel.js`）。結果は `builder.context.backdrop` / `backdropAlpha` に入る。
  - 背景の読み出しは `getTransmissionSample`。前面は `viewportOpaqueMipTexture()`（ミップつきの共有の `ViewportTextureNode`）を読み、
    裏面（`side === BackSide`）はモジュール内の別の `viewportMipTexture()` を読む。どれもモジュールの外に出ていない。
  - 読むミップの段は `log2(ビューポートの幅) × applyIorToRoughness(粗さ, ior)`。`textureBicubicLevel` が隣り合う2段を4点ずつ読む。
  - 粗さは `getRoughness` で 0.0525 より下にならない（ほかに法線の画面上の変化から小さな値が足される）。
    このため透明ガラスも、等倍でもともと約0.55段（1テクセル≒1.5画素）で読まれている。
- **写す処理**
  - `ViewportTextureNode` は `updateBeforeType = RENDER`。1回の `render()` につき1度、その描画で最初にこのノードを使う物の直前に
    `renderer.copyFramebufferToTexture()` を呼ぶ。
  - 写し先の `FramebufferTexture` は、その時の描画先（キャンバスか RenderTarget）の描画バッファと同じ大きさに毎回合わせられる
    （`updateBefore` が `image.width/height` を書き換える）。
  - WebGPU（`WebGPUBackend.copyFramebufferToTexture`）: 開いている描画パスを終え、`copyTextureToTexture` で 1:1 に写す。
    同じエンコーダで `textureUtils.generateMipmaps`（段ごとの描画パス）を作り、`loadOp: Load` で描画パスを開き直す。
  - WebGL2（`WebGLTextureUtils.copyFramebufferToTexture`）: `copyTexSubImage2D` で 1:1 に写し（MSAA の描画先なら同じ大きさの
    `blitFramebuffer`）、`generateMipmap` する。
  - どちらも拡大縮小しない。矩形は指定できるが、それは切り抜きで縮小ではない。
    サンプラーの `lodMinClamp` も、three の Texture からは設定できない（WebGPU の記述子で定数 0）。
- **「Destroyed texture used in a submit」の仕組み**（AGENTS.md の規則の裏づけ。考えられる仕組みで、S-05 の観察と合う）
  - 描画先ごとの写し先は `_cacheTextures`（WeakMap）に持つ。ただし `clone()` で作るので、元の写し先と `Source`（＝ `image`）を共有する
    （`Texture.copy` が `this.source = source.source` とするため）。
  - 大きさの違う描画先で透過を描くと、同じ `image` の大きさを書き換え合い、テクスチャが作り直される。
- **差し替えの口**
  - 材質の `backdropNode` は、透過の材質では照明モデルが `context.backdrop` を上書きするので効かない。
  - `material.contextNode = overrideNode(...)` は、置き換えたい節点（モジュール内の背景テクスチャ）に外から触れないので使えない。
  - 差し替えられるのは `material.setupLightingModel()` だけ。このときは、照明モデルの透過の部分を移植することになる。
  - 描画プログラムは `RenderObject.getMaterialCacheKey()` を鍵に共有される（`customProgramCacheKey()` と列挙できる性質。数値は 0/非0 だけ）。
    照明モデルだけが違う材質は、鍵を変えないと同じプログラムを使ってしまう。
- 参考: 旧来の `WebGLRenderer` には `transmissionResolutionScale` があった。不透明物を縮小した描画先にもう一度描く方式。
  WebGPURenderer（r186）には相当する設定がない。

## 作って測った近似（参考ブランチ c77e9d8）

- **方針**（純粋関数 `resolveBackdrop` / `backdropLod`）
  - 読む段 = `max(three の段, log2(1/transmissionScale))`。低は2段、中は1段、高は three のまま。
  - 曇りガラス（約4.9段）は下限より粗いので、どの品質でも同じぼけになる。
- **three 側**（`followTransmissionScale(material, scale)`）
  - 照明モデルを差し替え、r186 の `getIBLVolumeRefraction` を移植した。違いは段の下限だけ。
  - three の共有の背景画像を読むので、写す回数は増えない。
  - プログラムの鍵に段を足した。`clone()` でも方針を引き継ぐ。
- **センサー**
  - `auditBackdrop` と `sceneProbe.backdrop`（品質ごとの方針と、従わない材質）。
  - e2e `tests/e2e/S-10-backdrop.spec.ts` は両経路で8件。次を確かめた:
    - ガラスの外は1画素も変わらない
    - 1/4 では屈折が柔らかくなる
    - 下限が効かない所では、移植は three と同じ絵を描く（WebGPU は差0画素、WebGL2 は値1の差が16画素）
- AGENTS.md の規則（大きさの違う RenderTarget に透過を描かない）には触れない。新しい描画先は作らない。

## 退けた方法

1. **縮小した背景画像を自前で作り、材質に渡す**
   - 写す処理は描画パスの途中で走る。その時点の画面を縮小するには、パスを終えて縮小の描画（または縮小つきの blit）を挟み、
     パスを開き直す必要がある。r186 はその口を公開していない。
   - backend の非公開の内部を使えば WebGPU でも書ける（`renderer._currentRenderContext`、`backend.get(renderContext).currentPass` と
     エンコーダ、`textureUtils.generateMipmaps`、`_resetRenderContextData`）。ただし three の更新で黙って壊れやすく、
     姉妹作にもコピーする共通部品に入れるのは危険。
   - 入れ子の `renderer.render()` で縮小すると、WebGPU では外側のエンコーダ（写した中身を持つ）より先に提出される。
     このため1フレーム前の画面を読むことになると考えられる（試していない）。
   - 不透明物を縮小した描画先にもう一度描く（旧 WebGLRenderer の方式）と、描画呼び出しが約2倍（約250→約500）になり、予算の300回を超える。
2. **写す範囲を狭める（矩形）**: 切り抜きで、解像度ではない。ミップは全体を作り直すことになる。
3. **読み出しの段を下げる近似**（上の「作って測った近似」）: 効果が約2%で、見た目の代償と保守の負担に見合わない。

## 写す処理のコストの見積もり

測り方: 負荷シーンの手の玉の直前で、同じ大きさの写す処理をもう1回足し、フレーム時間の差を見た（参考ブランチ 57a12c5 の `?extracopy=`）。

| webgpu | 2回目（4巡、前後とも静か） | 1.096 | 1.111（+0.015） | 1.245（+0.15） |

- **WebGPU**: 背景画像1枚を写す処理の全体（パスの区切り＋1:1 のコピー＋ミップ）は、約 0.1〜0.15ms（負荷シーンの中品質の約1割）。
  - 大半はミップの生成（three は段ごとに描画パスを1つ使う）。
  - コピーとパスの区切りは約 0.02〜0.03ms。

- **親の判断**: 近似は採らない。r186 で背景画像の解像度を実際に変える手段は、描画解像度の行と動的解像度。

## 再現できる測り方（S-07 で推奨環境を測るとき）

### 準備

```sh
# 参考ブランチの計測用コミットを、別の worktree に出す（ブランチは動かさない）
git worktree add ../vidro-s10-ref 57a12c5
cd ../vidro-s10-ref
pnpm install && pnpm build
# ほかの Playwright ブラウザがいないこと（0 なら静か）。QUIET=1 は混雑していると終了コード3で止まる
ps -A -o command | grep ms-playwright | grep -c -- --type=gpu-process
```

下のスクリプトを worktree の外（例: `/tmp/bench-ab.mjs`）に保存し、**worktree のルートで**実行する。

### (a) 近似の効果（`?tscale=` の A/B）

- 品質ごとの表: `QUIET=1 SCENES=stress node scripts/bench-headed.mjs`（`artifacts/bench-headed.md`）
- 近似あり と なしを交互に3巡:

```sh
QUIET=1 ROUNDS=3 BENCH_SECONDS=5 node /tmp/bench-ab.mjs \
  'low:quality=low' 'low-full:quality=low&tscale=1' \
  'mid:quality=mid' 'mid-full:quality=mid&tscale=1' \
  'high:quality=high'
```

- 開く URL は `?scene=stress&<条件>&bench=5&warmup=2&dynres=0`（WebGL2 は `&webgl=1` が付く）。
- ヘッドあり、1920×1080、垂直同期なし。各巡で、WebGPU の全条件 → WebGL2 の全条件の順に開く。
- 最後に条件ごとの中央値を出す（巡の数が偶数なら上側）。
- 読み方: `low` と `low-full` の差が低での近似の効果、`mid` と `mid-full` の差が中での効果。

### (b) 写す処理のコスト（見直す条件 b）

```sh
QUIET=1 ROUNDS=4 BENCH_SECONDS=5 node /tmp/bench-ab.mjs \
  'mid:quality=mid' 'mid+copy:quality=mid&extracopy=copy' 'mid+copy+mips:quality=mid&extracopy=mip' \
  'low:quality=low' 'low+copy+mips:quality=low&extracopy=mip'
```

- `+copy` と素の差は、コピーとパスの区切りのコスト。
- `+copy+mips` と素の差は、背景画像1枚を写す処理の全体（ミップの生成を含む）。これをフレーム時間で割り、5%以上なら見直す。
- 写し足す処理は、手の玉の直前で同じ大きさで行う（負荷シーンの手の玉は既定で出ている。`?peek=0` にしない）。
- **WebGL2 の注意**: フレーム時間が CPU（ドライバ）で決まっている可能性がある。差が出なくても GPU の負担がないとは言えず、
  効果の上限を示すだけ。
- GPU のタイムスタンプは使わない（AGENTS.md: Apple/Metal では膨らむ）。
- 混雑したら数分おいてやり直す。

```js
import { mkdirSync, writeFileSync } from 'node:fs';
import { createRequire } from 'node:module';
import { join } from 'node:path';

const root = process.cwd();
const { chromium } = createRequire(join(root, 'package.json'))('@playwright/test');
const lib = await import(join(root, 'scripts/lib/preview-server.mjs'));
const { contendingBrowsers, GPU_ARGS, startPreview, UNCAPPED_ARGS, worktreePort } = lib;

const scene = process.env.SCENE ?? 'stress';
const backends = (process.env.BACKENDS ?? 'webgpu,webgl2').split(',');
const seconds = Number(process.env.BENCH_SECONDS ?? 5);
const rounds = Number(process.env.ROUNDS ?? 3);
const conditions = process.argv.slice(2).map((a) => {
  const i = a.indexOf(':');
  return { label: a.slice(0, i), query: a.slice(i + 1) };
});

const busyBefore = contendingBrowsers();
if (busyBefore > 0) {
  console.error(`contended: ${busyBefore} other browsers`);
  if (process.env.QUIET === '1') process.exit(3);
}
const server = await startPreview(worktreePort(523));
const results = [];
let browser;
try {
  browser = await chromium.launch({ channel: 'chromium', headless: false, args: [...GPU_ARGS, ...UNCAPPED_ARGS] });
  for (let round = 0; round < rounds; round++) {
    for (const backend of backends) {
      for (const c of conditions) {
        const page = await browser.newPage({ viewport: { width: 1920, height: 1080 }, deviceScaleFactor: 1 });
        const errors = [];
        page.on('pageerror', (e) => errors.push(e.message));
        page.on('console', (m) => m.type() === 'error' && errors.push(m.text()));
        const webgl = backend === 'webgl2' ? '&webgl=1' : '';
        await page.goto(`${server.url}?scene=${scene}&${c.query}&bench=${seconds}&warmup=2&dynres=0${webgl}`);
        await page
          .waitForFunction(() => ['done', 'error'].includes(window.__vidro?.status), undefined, { timeout: 120_000 })
          .catch(() => errors.push('timeout'));
        const p = await page.evaluate(() => window.__vidro);
        const b = p?.bench;
        const row = {
          round,
          backend: p?.backend ?? backend,
          label: c.label,
          frameAvgMs: b?.avgMs ?? null,
          frameP95Ms: b?.p95Ms ?? null,
          backdrop: p?.sceneProbe?.backdrop ? `${p.sceneProbe.backdrop.mode}/${p.sceneProbe.backdrop.scale}` : null,
          errors: errors.length,
        };
        results.push(row);
        console.log(
          `r${round} ${row.backend} ${c.label}: ${row.frameAvgMs?.toFixed(3)} ms (p95 ${row.frameP95Ms?.toFixed(2)}) ${row.backdrop} errors ${row.errors}`,
        );
        await page.close();
      }
    }
  }
} finally {
  await browser?.close();
  server.stop();
}
const busyAfter = contendingBrowsers();
const summary = {};
for (const r of results) {
  const k = `${r.backend} ${r.label}`;
  (summary[k] ??= []).push(r.frameAvgMs);
}
console.log(`\ncontended: before ${busyBefore}, after ${busyAfter}`);
for (const [k, v] of Object.entries(summary)) {
  const s = [...v].sort((a, b) => a - b);
  console.log(`${k}: median ${s[Math.floor(s.length / 2)].toFixed(3)} ms  [${v.map((x) => x.toFixed(3)).join(', ')}]`);
}
mkdirSync(join(root, 'artifacts'), { recursive: true });
writeFileSync(
  join(root, `artifacts/S-10-bench-ab-${Date.now()}.json`),
  JSON.stringify({ busyBefore, busyAfter, results }, null, 2),
);
```

- 結果の読み方: `contended: before 0, after 0` なら静か。どちらかが0でなければ、その回は比較に使わない。
- 写し足す処理は、参考ブランチ 57a12c5 の `src/scenes/stress.scene.ts` にある。
  - `?extracopy=mip` は `viewportMipTexture(refracted)`、`?extracopy=copy` は `viewportTexture(refracted)` を、
    重み 0.0001 で手の玉の色に足すだけ。
  - スイッチがなければ、シェーダは main と同じ。
