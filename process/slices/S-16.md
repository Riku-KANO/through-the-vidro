## 目的

S-06 の試作部屋（`room.events` に玉と雫の出来事が流れている）に、S-09 の音の基盤（`AudioEngine`、ぽぺん、ガラスの音、工房の残響）をつなぐ。
M0 ゲートの「覗く操作が気持ちいい」を、音のある状態で発案者が判断できるようにする。

設計書の該当節（`docs/design-snapshot.md`）:
- サウンドデザイン > ガラスの音: 手の玉は「ぽぺん」。覗く・置く・拾うのたびに鳴る。触れる・叩く・玉が当たるの3種類の強さ。大きい物ほど低い
- サウンドデザイン > 環境音: 空間の広さに合わせて残響を変える（狭い工房は短く）。3D 空間に配置し HRTF
- UI/UX設計 > 画面ごとの設計（読み込み）: ブラウザは操作があるまで音を鳴らせないため、ここで一度押してもらう
- コアメカニクス > 基本の動作: 拾えないときは玉が小さく震えて知らせる。調べる＝光の雫に触れる
- アセットリスト > 音: ビードロの音 4（覗く、置く、拾う、震える）

## 出来事と音の対応（`cueFor`、`src/game/prologue/sound.ts`）

| 出来事（`room.events`） | 音 | 出どころ（HRTF の Emitter） | 理由 |
|---|---|---|---|
| `peekStart` | ぽぺん「覗く」（B5→B5） | 手 | 設計書: 覗くたびに鳴る |
| `peekEnd` | **鳴らさない** | — | 設計書はビードロの音を4種（覗く・置く・拾う・震える）としか書いていない。下ろす音は書いていないので無音を既定にした。ただし UIの原則3（入力に0.1秒以内に音と動きで応える）とは食い違いうる（判断待ち1） |
| `place` | ぽぺん「置く」（D6→A5） | 手 | 設計書: 置くたびに鳴る。手が玉を放す瞬間の音として手から（判断待ち2） |
| `pickup`（作業台から・台座から） | ぽぺん「拾う」（A5→D6） | 手 | 設計書: 拾うたびに鳴る。玉が手に入る |
| `shake`（置いたまま覗こうとした・橋の上で拾おうとした） | ぽぺん「震える」（A5/B5 の交互） | 玉のある所（台座） | 設計書: 拒否は玉が小さく震えて知らせる。震えるのは台座の上の玉で、手は空（下の「手の位置からの例外」） |
| `dropTouched` | ガラス「触れる」、仮の大きさ 0.14m（E5） | 雫 | 基本の動作: 調べる＝光の雫に触れる。強さ3種のうち「触れる」。大きさは耳で決める仮の値（判断待ち3） |
| `dropTaken` | ガラス「叩く」、ビードロの大きさ 0.15m（D5） | 玉のある所（台座） | 雫が飛んでビードロに入る瞬間、ビードロが小さく鳴る。強さは中（判断待ち3） |

- 音の高さは S-09 の大きさ→音程の規則（`glassPitch`）から: 雫は仮の 0.14m → E5、ビードロ 0.15m（手の玉の直径）→ D5（根音）。ぽぺんの音型は S-09 の `POPEN_PATTERNS` のまま。
  雫の 0.14m は描いた雫の寸法ではない（`room-art.ts` の雫は幅約0.11m・高さ約0.24m。規則の「最も長い寸法」で取ると F#4 でビードロより低く、幅で取ると A5）。
- **手の位置からの例外**: spine の「玉の音は手の位置から HRTF で鳴る」は、手に持っている玉の音（覗く・置く・拾う）で満たす。震えるは、玉が台座に置かれて手が空のときにしか起きない（`session.ts` の `refusePeek` と `atPedestal`）ので、震えている玉＝台座から鳴らした。
  手から鳴らすと、目の前で台座の玉が震えているのに音は空の手から聞こえる（絵と音の位置が食い違う）。`sourcePoint` は「玉のある所」を手・作業台・台座から選ぶので、1行で手に変えられる（判断待ち2）。

## 作り（`createPrologueSound`）

- **最初の操作の中で AudioContext を作る**: S-09 の audio-lab は読み込み時にエンジン（AudioContext）を作って止めておく作りだが、ここでは最初の操作
  （pointerdown / pointerup / click / keydown / touchend、`navigator.userActivation.isActive` が真のとき）の中で `new AudioContext()` を作り、
  `AudioEngine.create({ context })` に渡す。操作の前にはコンテキストが存在しないので、実機の Chrome の自動再生の方針による警告
  （「The AudioContext was not allowed to start…」）が出る余地がない。それまでの出来事は `refused` に記録するだけで、再生器へは二度と渡さない（溜めない）。
  エンジンが受け取ったコンテキストは閉じないので、`dispose` で自分で閉じる。2回目以降の中断（タブの切り替え等）は `engine.bindUnlockGestures` が次の操作で再開する。
- 残響は `VIDRO_ROOMS.workshop`（T60 0.6秒）、音量と残響への送りは `VIDRO_VOLUMES` / `VIDRO_REVERB_SEND`（S-09 の初期値）。
- **HRTF の Emitter 3つ**（効果音のバス）: 手（毎フレーム、カメラの座標系の `handOrbCenter` をワールドへ。覗く進み具合・手の有無で動く。鳴っている途中も手と一緒に動く）、
  玉（作業台か台座。鳴らす瞬間に置く）、雫（`DROP`）。聞き手は毎フレームのカメラ（位置・前・上）。
- **片付け**: `dispose` で購読を外し、操作の待ち受けを外し、Emitter を外し、エンジンを約20msで絞ってから切り離し、コンテキストを閉じる。
  シーンの `dispose`（直接モードとホーム経由の両方）から呼ぶ。
- AudioContext を作れない環境では `unavailable` になり、部屋は無音で続く（例外を投げない）。
- 観測口 `window.__vidro.sceneProbe.sound`（`SoundProbe`）: `state`（操作前は `locked`、後はコンテキストの状態）、`unlocked`、`room`、`panning`（各 Emitter のパンの方式）、
  `voicesStarted` / `voicesDropped`、`played`（`{ event, cue, source, distance }` の列、最大64と総数）、`refused`、`emitters`、`subscribed`、`disposed`。getter なので、シーンが替わった後も古い probe を持っていれば片付いたかを読める。

## 発案者の耳で確かめてほしい点（S-07 で一緒に見る。センサーでは確かめられない）

`pnpm dev` → `http://localhost:5173/?scene=prologue-proto`（ホームから。「はじめる」の1回目のクリックで音が始まる）、`&direct=1`（工房から。最初のクリックで始まる）。ヘッドホン推奨。

1. **音量の釣り合い**: 手のぽぺん（0.5m、型の大きさ 0.5）に対して、雫に触れる音（ガラス「触れる」0.2、約0.8m）と、向こう岸から聞く「雫がビードロに入る」音（ガラス「叩く」0.45、台座まで約4m → 距離で約1/4）が小さすぎないか。とくに後者は向こう岸からでも聞こえるか。
2. **ぽぺんの間**: 覗くと玉がせり上がる 0.25秒の間に「ぽ」→（130ms）→「ぺん」が鳴る。せり上がりと音の頭が合っているか。覗くを素早く繰り返したとき、ぽぺんが重なってうるさくないか（覗くたびに必ず鳴る）。
3. **下ろすときの無音**（判断待ち1）: 覗くを離したとき音がないことが物足りないか、静かでよいか。とくに切り替え式（`?peek=toggle`）では2回目の押下が明らかな入力なのに、音がなく玉が下がる動きだけになる（UIの原則3）。

5. **出どころの方向感**（HRTF）: 手のぽぺんが右下の手から聞こえるか、置くの音が手から聞こえて違和感がないか（判断待ち2）。雫の音が雫の方向から聞こえるか。

## 判断待ち

1. **peekEnd（覗く終わり）は無音を既定にした**。
   - 無音の根拠: 設計書は「覗く・置く・拾うのたびに鳴る」（サウンドデザイン > ガラスの音）「ビードロの音 4: 覗く、置く、拾う、震える」（アセットリスト > 音）とだけ書き、下ろす音を書いていない。
   - 反対の根拠: UI/UX設計 > UIの原則3「入力から0.1秒以内に必ず音と動きで反応する」。操作とカメラ > 入力の割り当て「覗く操作は長押しと押すたびに切り替えを設定で選べる」の切り替え式では、2回目の押下が明らかな入力なのに音がない（長押しでは離す操作）。
   - 鳴らす案（どれも `cueFor` の数行）: (a) ぽぺん「覗く」を小さく使い回す（ビードロの音の4種は増えない）、(b) 切り替え式のときだけ鳴らす（出来事に操作の方式を足す必要がある。room.ts の範囲）、(c) 下ろす専用の音型を足す（アセットが5種になる）。
2. **音の出どころ**: 覗く・置く・拾うは手、震えるは玉のある所（台座）、雫に触れるは雫、雫が入るは玉のある所。spine の「玉の音は手の位置から」に対して、震えるだけは手が空のときに起きるので台座からにした（上の「手の位置からの例外」）。
   置くを台座から鳴らす案（置いた瞬間、玉はもう台座に描かれている）もある。どちらも `cueFor` の `source` を変えるだけ。
3. **雫の音の強さと高さ**（設計書に数値なし）: 触れる＝ガラス「触れる」・仮の大きさ 0.14m（E5）、雫が入る＝ガラス「叩く」・ビードロの大きさ 0.15m（D5）。
   雫の音程をどの寸法で決めるか: 規則（`glassPitch` の「最も長い寸法」）に従うと描いた雫は高さ約0.24m で F#4（ビードロより低い）、幅約0.11m なら A5。今の 0.14m はどちらでもなく、「ビードロより一段高い」ように選んだ耳で確かめる仮の値。
   設計書の「光の雫を拾うたびに生成音楽の層が重なる」は M1（生成音楽）の範囲で、ここでは入れていない。
4. **残響は部屋の全体で工房**（spine の指定どおり）。試作部屋は工房（ドームの中）と外の一本道・谷・橋を含む。外を別の空間（短い・乾いた、または谷の広がり）にするかは設計書にない。
5. **台本（`?autoplay=1`）は無音**: 操作がないので音は始まらない（S-04 の `AudioGate.skip()` と同じ扱い）。台本の途中でクリックすると、それ以降の出来事から鳴る。

## 残件

- **AudioContext が2つ**: ホーム経由では、S-04 の `AudioGate`（ホームの雫の仮の音）と、このスライスのエンジンが、同じ「はじめる」のクリックでそれぞれコンテキストを作る。
  本編では1つのエンジン（`src/core/audio`）にまとめる（`src/ui` は範囲外のため触っていない。提案2）。
- **実機の Chrome の自動再生の警告はセンサーで見えない**: Playwright の Chromium（ヘッドレス）は、`--autoplay-policy=user-gesture-required` を渡しても、Playwright の既定の
  `--autoplay-policy=no-user-gesture-required` を外しても、操作前に作った AudioContext が running で始まり、警告も出なかった（このスライスで確認）。
  このため「操作前にコンテキストを作らない」ことを構造で守り、e2e は操作前の `state === 'locked'`（コンテキストがない）で確かめている。実機での警告の有無は未確認（S-07）。
- `scenes.spec.ts` のセンサーは各シーンを操作なしで約5秒開くだけなので、試作部屋の音の経路は通らない（コンテキストを作らない）。音は S-16 の e2e が確かめる。
- 足音・環境音のループ・生成音楽は M1 以降（`src/audio/`）。
- 2つ目以降の中断（タブの切り替えなど）からの再開は S-09 のエンジンの `bindUnlockGestures` に任せている。e2e では確かめていない。

## 分かったこと

1. **Playwright の Chromium では、自動再生の方針を変えられなかった**: `--autoplay-policy=user-gesture-required` を渡しても、Playwright の既定の
   `--autoplay-policy=no-user-gesture-required` を `ignoreDefaultArgs` で外しても、操作の前に作った AudioContext は running で始まり、console に警告も出なかった（ヘッドレス、`about:blank`）。
   実機の Chrome の自動再生の警告は、センサーでは捕まえられない。音のコンテキストは「操作の中でしか作らない」という作りで防ぐのが確実。
2. **probe を getter で作ると、シーンが替わった後の状態を e2e から読める**: 品質の切り替えでシーンが作り直されると `sceneProbe` は新しいインスタンスのものに替わるが、
   古い probe のオブジェクトを `window` に持っておけば、その getter は古いインスタンスを読み続ける。片付けの検査に使った。取るのは操作の前（切り替えと競合しない時点）。
