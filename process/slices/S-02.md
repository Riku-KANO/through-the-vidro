- 基本材質（MeshBasicNodeMaterial）には emissive の色がなく、継ぎ目の光を足すと `updateColor` が undefined を読んで毎フレーム例外 → 色を持たない材質は vec3(0) を基にする。
- 覗いている間の画像に裏の物が映らない: `renderGroup` の共有 uniform は1フレーム内の2回目の描画呼び出しで更新されず、「裏の画像を描いている」切り替えが届かなかった → 切り替えだけ物ごとの uniform にした（球のデータは両パスで同じなので共有のまま）。
- **透過（transmission）と覗くパス**（S-05 からの共有、2026-10-21）: WebGPU 経路では、透過の材質を画面と違う大きさの描画先に同じフレームで描くと
  「GPUValidationError: Destroyed texture … used in a submit」でフレーム全体が捨てられる（three r186。WebGL2 では出ない）。
  lab では透過の物は台座の玉だけで、置いている間は覗けないため実際には起きていなかった（警告・エラーを含む全コンソールを確認して0件）が、S-06 で S-01 の透過ガラスが共通の層に入ると起きる。
  回避策: `LayerField.assign` が透過の材質を持つ裏・共通の物を**覗くパスに入れない**（専用のチャンネル `mainOnly` に置き、本描画だけで描く）。
  代わりに覗くパスだけが描く子（チャンネル `peekOnly`、同じ形状、同じ材質から透過を抜いた半透明）を自動で足す。覗く像に出さないときは `{ inPeek: false }`（lab の台座の玉）。
  単体テスト `field.test.ts`・`layers.test.ts` と、e2e がコンソールの警告も含めて GPU の検証エラーで落ちるようにした。手の玉の合成は最初から transmission を使わない自前の合成
  （`texture(rt, 屈折した座標)`）。
- **影**（S-05 からの共有）: 影マップは1フレームで最初に使う描画で作られるため、覗くパスが先だと表の物が影に入らない → `assign` で光源の影のカメラの layers を本描画の範囲に固定し、

## S-06 での統合に必要な口（API）

入口は `src/layers/index.ts` と `src/game/orb/index.ts`。

- **描画**: `renderer.render` の代わりに `new PeekPipeline({ renderer, scene, camera, field, peekScale: quality.peekScale, environment })` を作り、
  毎フレーム `pipeline.render({ center, radius, peek, visible, sunDirection })`。手の玉の位置は `handOrbCenter(peekAmount, presence, t)`。
  RenderPipeline（AgX の出力を含む）を内側で持つので、S-05 の動的解像度・アンチエイリアスと合わせるときはこの合成ノードの後ろにつなぐ。
- **層**: `field.assign(obj, 'surface' | 'back' | 'shared')`（光源も 'shared'）。`scene.add(...field.membranes)`。
  毎フレーム `field.setSpheres(orbSpheres(orbs, pedestals).map((s) => ({ center: s.center, radius: s.radius, glow: boundaryGlow(s.materialize) })))`。
  材質は `*NodeMaterial` であること（S-01 のガラスはそのまま `assign` に通せる）。同じ材質を別の層の物に使うと自動で複製する。
- **玉と規則**: `createOrbs(smallCount)`、`placeOn` / `takeBack` / `stepOrbs`、`canPeek` / `canPlace` / `canPickUp`。
- **S-03（プレイヤー）との口**: `stepPeek(state, { wantPeek, allowed: canPeek(orbs) }, dt)` → `peekAmount(state)`。
  移動速度は `peekMoveSpeedMultiplier(amount)`（0.5 = `PEEK_MOVE_SPEED_FACTOR`）、視野角は `peekFovOffset(amount)`（-6度 = `PEEK_FOV_DELTA_DEG`）。
  入力は「覗く（長押し／切り替えは入力側）」と「調べる（置く・拾う）」の2つを受け取る。
- **当たり判定**: 裏の足場を `splitFooting(id, box, 0.4)` で区画に分け、`activeSegmentIds(segments, spheres)` の区画だけ Rapier の `collider.setEnabled(true)`。
  拾う前に `canPickUp(orbs, id, { pedestals, footing, feet })`。

## 判断待ち（発案者へ）

1. **手の玉の屈折の見え方**: 本物の15cmのガラス玉を目の近くで覗くと像は上下左右が逆になる。今は屈折の一部だけを使って**正立の拡大（中央で約1.2倍、縁で強く曲がる）**にしている。
   覗いた像の位置が世界と合うので「行き止まりの先に橋がある」が読みやすい、という理由。倒立のレンズボールの方が「ガラス玉らしい」とも言えるので、S-07 の体感評価で決めてほしい（定数 `REFRACT_PEEK` で調整できる）。
2. **拾う規則の解釈**: 「実体化した足場の上にいるときは回収できない」を、足元の裏の足場がその玉を外すと当たり判定を失うときだけ拒否する、とした。別の玉の球が足場を支えていれば拾える。
   「道を小玉で保ったまま、主玉を持って先を覗く」（ガラス玉の性質の成長）を成り立たせるため。字義どおり「裏の足場の上では常に拾えない」にするかを確認したい。
3. **覗いている最中の左クリック**: 入力の表で「覗きながら左クリック」は鳴らす（エリア3から）なので、lab では覗いている間の左クリックは何もしない（`ring-unavailable`）。
   E（とゲームパッドの A）は覗いていても置く・拾う。置くと手から玉が離れるので覗きは自動で終わる。規則 `canPlace` には覗いているかを入れず、入力の振り分けで扱う（レビューの指摘で変更）。
4. **見えない柵の範囲**: 「範囲の境目は光の膜として見え、外へは踏み出せない」が、(a) 裏の足場の上にいるときだけ球の外へ出られない、(b) 球の中にいるときは常に出られない、のどちらか。(b) だと拾うまで部屋に閉じ込められる。
5. **仮の数値**（設計書にない）: 台座に届く距離 2.5m と向き（視線から75度以内）、拾った玉が手に戻る時間 0.25秒、手の玉の半径 7.5cm、
   台座の玉が震える時間 0.45秒と振れ幅 1.2cm（拒否のときは玉と境目も短く光る）、裏の足場の区画の長さ 0.4m、覗く像の中の透過ガラスの代役の不透明度 0.35、継ぎ目の光の色。
6. **色収差と品質プリセット**: 低品質の「分散なし」でも、手の玉越しの色収差（画面の仕上げの規則）はかけている。低品質で切るかどうか。
7. **実体化の曲線の感触**: 共通の曲線（ゆっくり始まって粘りながら止まる）だと、半径の大半は最初の0.45秒で広がり残りはゆっくり止まる。「波紋が広がる」には合っていると判断したが、S-04 の曲線に差し替えたときに見直す。
8. **覗くパスの中の透過ガラス**: WebGPU の不具合を避けるため、透過の物は覗いた像では「同じ材質から透過を抜いた半透明の代役」で描く（自動）。
   設計で透明ガラスを使う橋やドームも玉越しに見えるが、屈折はしない。代役の見え方で足りるかは S-06 で S-01 の材質と合わせて確かめる。

## AGENTS.md への提案（親が反映）

- 技術の決まりごとに追加（観測ベース）: 「1フレームの中で描画ごとに値を変える uniform（例: 裏の画像を描く間だけの切り替え）は `renderGroup` に置かない」。
  この描画の流れ（自前の描画先への描画 → RenderPipeline の pass()）で、`renderGroup` の切り替えが2回目の描画に届かないことを観測した。three r186 の共有グループは版の番号で更新される（`NodeManager.updateGroup`）ので根本原因は未特定。
  再発は e2e の画素テスト（玉の中の裏の層の有無）で検出できる。
- 技術の決まりごとに追加: 「TSL の `smoothstep(a, b, x)` は a < b で書く。逆順は GLSL/WGSL で未定義（減る形は `1 - smoothstep(b, a, x)`）」
- センサーに追加: 「実時間で遷移の長さを測る e2e は、`ready` の後に少し待ってから測る（起動直後のパイプラインのコンパイルで dt が 0.1 に切られ、遷移が長く見える）」
- センサーに追加（`tests/e2e/scenes.spec.ts`、範囲外なので提案）: コンソールの警告のうち GPU の検証エラー（`GPUValidationError`、`Destroyed texture`、`used in a submit`）も失敗にする。
  WebGPU の検証エラーは警告として届くことがあり、そのときはフレームが捨てられても今の判定では緑になる。S-02 の e2e は対応済み。
- 技術の決まりごとに追加（S-05 の AGENTS.md 追記と同じ趣旨）: 「覗くパス（画面と違う大きさの描画先）に透過の材質を入れない。`LayerField` が自動で外す」
- S-07 への提案: 覗く／覗かないのフレーム時間の差を推奨環境で測る（ヘッドレスの M5 Pro では WebGPU +0.15ms、WebGL2 差なし）。
