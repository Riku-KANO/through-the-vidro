## 判断待ち

1. **視野角は縦か横か（S-06 の前に決めたい）**: 設計書の「視野角70度(60〜100)」を three.js と同じ**縦**の視野角として扱った（16:9 で横約102度、縦100度は横約130度で魚眼に近い）。60〜100 は PC の FPS では横の視野角によくある幅でもある。構図（柱4）と S-01/S-06 の絵作りに効く。横の意図なら `PlayerController.applyToCamera` の1か所で縦に変換する。
2. **ゲームパッドの早歩き**: 「左スティック押し込み」を、押したらスティックを戻すまで続くラッチにした（押し込み続けるのは指が疲れるため）。
3. **縁で止まる対象**: 0.32m を超える落差はすべて縁として止める。わざと飛び降りられる場所を作るなら別の仕組み（例: 飛び降り用の印）が要る。
4. **ロックが外れたら理由を問わず pause を出す**（Esc 以外にタブの切り替えなどでも）。ポーズ画面を出すかは S-04/S-06。
5. **鳴る を得る前の「覗きながら左クリック」は「置く・拾う・調べる」になる**（鳴らすは `canRing` が true のときだけ）。入力の表は「鳴らす(エリア3から)」、性質の表は「エリア2クリアで鳴る」で、いつ true にするかは S-06 以降。
6. **Rapier の配布サイズ**: compat 版は WebAssembly を base64 で埋め込むため、walk-lab のチャンクが 4.37MB（gzip 1.68MB）。初回読み込み15MB の予算に対して大きい。非 compat 版（`@dimforge/rapier3d`、wasm を別ファイルで配信）への切り替えは依存の変更なので発案者の判断。

## S-06 での統合に必要な口（API）

```ts
// 物理（世界はシーンが持ち、S-02 の裏の足場も同じ世界に入れる。毎フレーム player.update の前に world.step()）
import { createWorld, initPhysics } from './game/player/physics';
const R = await initPhysics();
const world = createWorld();

// 体とカメラ
import { PlayerController } from './game/player/player';
const player = new PlayerController(world, {
  feet, yaw, pitch,
  settings: { fovDeg: 70, headBob: 1 },        // 視野角 60〜100、揺れ 0〜1（0 でオフ）
  filter: (collider) => true,                   // 当たり判定から外したいものがあれば（センサーは常に除外）
});
player.update(dt, { move, sprint, lookYaw, lookPitch });
player.applyToCamera(camera);                   // camera.position / rotation / fov を毎フレーム書く
// 覗く（S-02 の関数をそのまま使う）。delete で戻る
player.modifiers.set('peek', { speedMultiplier: peekMoveSpeedMultiplier(a), fovOffsetDeg: peekFovOffset(a) });
player.feet / player.eye / player.velocity / player.grounded / player.fovDeg / player.teleport(...) / player.dispose()

// 入力
import { InputSystem } from './game/input/input-system';
const input = new InputSystem(canvas, { bindings, settings: { peekMode: 'hold' } });
input.canPeek = () => !orbPlaced;    // 玉を置いているときは覗けない（覗いていれば終わる）
input.canRing = false;               // 鳴る を得たら true
input.suspended = true;              // 演出中・キー設定中は入力を預かる（覗きも終わる）
input.on((e) => { /* peekStart | peekEnd | interact | ring | orbStep{delta} | orbSelect{index} | pause */ });
input.update(dt); input.move; input.sprint; input.consumeLook(); input.peeking; input.locked; input.cancelPeek();
// S-02 の stepPeek には { wantPeek: input.peeking, allowed: canPeek(orbs) } を渡す

// 割り当ての保存と設定画面（S-04/S-06）
import { DEFAULT_BINDINGS, parseBindings, rebind } from './game/input/bindings';
```

- **視野角と速度は `player.modifiers` だけで変える。S-02 側で `camera.fov` を書かない**（`applyToCamera` が毎フレーム書くので、上書きされるか -12度になる）。S-03 の `PEEK_MODIFIER` は設計書の値の写しで、統合後は S-02 の `peekMoveSpeedMultiplier` / `peekFovOffset` を正にしてよい。
- **裏の足場**: S-02 は区画を `collider.setEnabled` で切り替える。立っている区画が消えると体は落ちる（`player.test.ts` で確認）。区画の継ぎ目は地面の測定の球（0.1m）がまたぐので縁と読まない。
- **球の縁の見えない柵**（S-02 で未実装）: 足場が球の縁で途切れて0.32m を超える落差になる所は、S-03 の縁の判定がそのまま柔らかい柵になる。平らな床の上で球の外へ出さない柵は別に要る。
- walk-lab の「覗く」は S-02 の代役（0.25秒で修飾子を混ぜるだけ）。

## 分かったこと・失敗をルールに変える

- **Rapier のキャラクター制御はカプセルの丸い底で段の角を斜面のように上る。** 衝突後の速度を慣性に戻すと段ごとに詰まる（6段に7.4秒）。慣性は「望んだ速度」で持ち、実際の移動は別に記録する（6段に3.4秒）。円柱の体は段で0.2m瞬間移動するので採らなかった。
- **Rapier の滑りはたまに1歩だけ短く止まる**（丸い柱に沿う途中で 0.8→0.07m/s が1フレーム）。設定（offset、normal nudge）では消えない。残りのうち壁に沿う成分だけでもう一度計算すると消える（速度は増えない）。
- **接地中の縦の移動**: ちょうど0だと snap が体を床に押し込むことがあり、重力を残すとカプセルの底が skin に沈んで柱の根元（床と柱の角）に引っかかる。0 のままにして、沈んだら地面に戻す補正で両方を避けた。
- **Rapier の cylinder は歩く面に使えない**: 平らな上面への下向きのレイの約1/80、球の形のキャストの約1/2000 が外れる。round cuboid は面の上では外れないが、丸みの始まり付近でまれに外れる（レイと球が同時に外れることはなかった）。
- **「引っかからない」のテストは実際の移動量で測る。** 望んだ速度で測ると壁に押し付けても 1.4m/s と出て、何も確かめていなかった。
- **ヘッドレス Chromium でも Pointer Lock は効く。** ただし合成の Esc はブラウザのロック解除を起こさずページに届く。ページに Esc が届いたら自分で解除する。
- **赤の証跡は「モジュールがない」では足りない**: 振る舞いの判定が落ちることを、仮の実装（スタブ）に対して確かめて残す。
- KCC の skin の中で体が数mm上下するので、目の高さは体の下の地面から測る。
