## 結論

- **仕上げのつなぎ方**: `PeekPipeline` の合成の後ろに、負荷シーン（`stress.scene.ts`）と同じ順の仕上げをつないだ。
  - 順: **合成（線形の HDR）→ 抑えたブルーム → `renderOutput`（AgX と出力の色空間）→ 画面と同じ大きさの画像（`rtt`）→ プリセットの SMAA（中・高）／FXAA（低）**。
  - `RenderPipeline.outputColorTransform = false` にした（AgX を最後にもう一度かけない）。
- **`OrbComposite` は変えていない**。
  - 合成はもともと AgX を持っていなかった。`vec4(color, 1)` で線形の色を返し、変換は `RenderPipeline` の出力の変換がかけていた。
  - ブルームはその線形の色にかかる。玉越しの色収差と、覗く間のぼかしは合成のまま。
- **ブルームの値**: 強さ・半径・しきい値は負荷シーンと同じ（0.25・0.3・0.9。しきい値は線形の輝度）。4通りを試して決めた（「見た目の確認」）。
- **ブルームの解像度**: ここだけ負荷シーンと違い、**4分の1**（負荷シーンと three の既定は半分）。
  - 半分のままだと、1080p で試作部屋が負荷シーンより重かった（1.15 対 1.10 ms）。4分の1では負荷シーン以下（「計測値」）。
  - 4分の1だと、明るい所を取り出すパスの1画素が画面の 4×4 を代表する。
    - 合成を一度画像に保存し（`rtt`）、±1 画素ずらした4点のバイリニアの平均を読んで、ブロック全体を覆う。
    - 1点だけ読むやり方では、視点が回ると小さい光がブルームに出入りした（レビュー2巡目の指摘。測ると半分の解像度の約2.7倍の揺れ）。4点にすると、半分の解像度と同じ程度に戻った。
- **開発用のスイッチ** `?finish=0|aa`: 同じ画面を仕上げの段ごとに比べるため。
  - `0` = AgX だけ（S-17 の前の絵）。
  - `aa` = ブルームなし。
  - なし = 全部。
- **光の雫**:
  - 近くで狙っているとき（向こう岸、「E 触れる」。狙うと芯が1.5倍に明るくなる）は、はっきり滲む（雫のまわりの輪 +9.2/255）。
  - **行き止まりから見た雫（5m、狙っていない）は、ほとんど滲まない**（+1.2/255。その大半は近くの灯りと台座の玉の裾）。
  - そこでの雫は、灯り（乳白のガラス）や照らされた台座の玉より暗い。夜明けの空と同じくらいの明るさで描かれている。
    - 画面の輝度: 雫 0.75、灯り 0.8〜0.89、台座の玉 0.96、暖色の空 0.67〜0.9。
  - 空や照らされた面を滲ませずに、遠くの雫だけを滲ませるしきい値はない。しきい値ではなく美術（`room-art.ts`、範囲外）の問題として、判断待ち1 に書いた。
  - **判断が出るまで、受け入れ条件1は完了として扱わない。**

## 実装

- `src/game/orb/peek-pipeline.ts`
  - `PeekPipelineOptions` に `antialias`（`quality.antialias`）と `finish?: FinishMode` を足した。`finishModeFrom(params)` が `?finish=0|aa` を読む。
  - `finish()` の流れ:
    1. 合成を画面と同じ大きさの画像に保存する（`rtt`）。
    2. ブルームには、その画像を ±1 画素の4点でバイリニアに読んだ平均を渡す（`bloom(…, 0.25, 0.3, 0.9)`、`setResolutionScale(0.25)`）。
    3. 保存した合成にブルームを足す（`vec4(rgb + glow.rgb, 1)`）。
    4. `renderOutput` → `rtt` → `smaa`／`fxaa`。
    - 画素の大きさは uniform（`uTexel`）で、毎フレーム描画の大きさから入れる。
  - 仕上げのノード（保存した合成、ブルーム、表示用の `rtt`、SMAA/FXAA）は `dispose()` で捨てる。
    - `smaa()` に渡した画像は、SMAA の `dispose` では捨てられない。そのため `rtt` を自分で作って持つ。
  - 透過の材質は、仕上げのどのパスにも描かない。
    - どれも全画面の四角だけ（ブルームの小さい段も同じ）。
    - 新しい材質は NodeMaterial の全画面の四角だけで、透過はない。
- `src/game/prologue/room.ts`: `antialias: quality.antialias` と `finish: finishModeFrom(ctx.params)` を渡すだけ（2行。後者は上の逸脱）。
- `src/scenes/layers-lab.scene.ts`: 同じ2つの引数（PeekPipeline の引数が変わったため）。
- `tests/e2e/S-17-finishing.spec.ts`（新規、両経路、計約75秒）
  - **試作部屋**: 4つの視点 ×3つの段を撮り、ブラウザの中で PNG を輝度にして比べる（S-06 の e2e と同じ方法）。どれも `dynres=0`。
    - 視点: 行き止まりで覗く前（`peekHold=0`）、覗いている（`peekHold=1`）、実体化した橋（`growHold=1`）、向こう岸で雫を狙う（`spawn=far&growHold=1`）。
    - 低品質（FXAA）は、覗く前の視点の2つの段。
    - 描画呼び出しと三角形の予算も見る。
  - **layers-lab**: `peek=hold` で3つの段。玉の中のコントラスト、ブルームが控えめなこと、AA が何かを変えて縁を減らすことを見る。
  - **揺れ**: 覗く前の視点で視点を少しずつ回し、ブルームが足す揺れを見る。
  - 撮った PNG は `artifacts/screens/S-17/<webgpu|webgl2>/` に置く。
  - 数値は `artifacts/S-17/finishing-<経路>.json`・`layers-lab-<経路>.json`・`turning-<経路>.json` に置く。

**1巡目**（ブルームの値を4通り、解像度は半分）:

## 判断待ち（発案者へ）

1. **遠くの光の雫を光として見せるか**
   - 今の美術では、雫は狙ったとき（近く、「E 触れる」）にだけ芯が明るくなり、ブルームで滲む。
   - 行き止まりから見た雫（5m、狙っていない）は、夜明けの空と同じくらいの明るさで、滲まない。
   - 道は3つ:
     - (a) **美術**: 雫の芯を、合成の後でしきい値（線形の輝度 0.9）を十分に超える明るさにする（今は虹色ガラスの殻を通して暗く見える）。
       `room-art.ts`（S-06 の範囲）の変更。次の場所が先に見える（空間の可読性 6）の助けにもなる。
     - (b) **発光だけを滲ませる**: three の `mrt({ output, emissive })` で、場面のパスから発光の画像も取り、ブルームをそれにかける。
       何が滲むかを、明るさではなく材質で決められる。ただし、`room-art.ts` で雫の芯を発光として描く変更と、場面のパスの書き込みが1枚増える分の帯域が要る。
     - (c) **しきい値を下げる**: 空と照らされた面まで滲むので取らない。
2. **実体化の途中の波面の光の強さ**: ブルームが加わって、近くの切り口の白い帯がやわらかく広がる。S-06 の残件と一緒に、S-07 の体感で決める。
