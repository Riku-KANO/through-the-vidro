## シミュレーション（`scripts/sim/dynres-noise.mjs`）

```
node scripts/sim/dynres-noise.mjs            # 直す前 = 98185af（S-13 の分岐元）、直した後 = 作業ツリー。各200回（長いセッションは100回）、約6秒
node scripts/sim/dynres-noise.mjs --before none --runs 50 --only prop,flat
```

- governor を、アプリと同じ取り方（`src/core/perf/load-sim.ts` の `driveLikeApp`: 8フレームに1回、2フレーム遅れで読む、古いエポックは捨てる）で動かす。
  フレーム時間は垂直同期（GPU 時間を 16.7ms の倍数に切り上げ）。直す前のコードは `git show 98185af:...` を vite の oxc で変換して読み込む（`scripts/sim/lib/load-ts.mjs`）。
- 揺れは対数正規 AR(1)。z ← ρz + √(1−ρ²)·σ·ε、ρ = exp(−Δt/τ) で、GPU 時間に exp(z − σ²/2)（平均1）を掛ける。σ は対数での揺れ幅、τ は揺れが続く時間。
  実機の垂直同期ありの span は数秒の単位で揺れた（S-08: 軽い負荷で 3.6〜6.7ms、S-11: 重い負荷で 2.9〜16.5ms）。
- 跳ね（`spikes`）: 各フレームが確率 0.1 で3〜6倍になる（実機の閉ループで見た）。二つの周波数（`regime`）: ×1 と ×1.78 を行き来し、高い状態に平均1秒、低い状態に平均2秒いる（σ0.1 を重ねる）。
- 種は固定（場面ごとの素数 × 回の番号）。同じコードなら同じ表が出る（最終のコードで2回実行して一致を確かめた）。
- 負荷: 「比例」は GPU 時間が画素数に比例（倍率の2乗）、「比例しない」は倍率によらず一定。目標は「実際の目標」16.7ms（縮める閾値 13.3ms）、
  または試験用の 6ms（高品質、S-08・S-11 の閉ループと同じ）。「下限」は、プリセットごとの実際の下限（中品質 0.51、高品質 0.60）。
- レビュー担当の数値（P2-1 の 102/200 など）とは少しずれる。レビュー担当のシミュレーションは揺れを毎フレーム 16.7ms ずつ進めていたが、
  ここでは実際のフレーム時間（過負荷では 33ms）で進めるため、同じ τ でも実時間での揺れが短い。
