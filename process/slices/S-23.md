### 命名規則（設計書の表に合わせ、足りない所を仮で決めた）

`<エリア>_<種類>_<番号>[_front|_back|_col][_LOD0|_LOD1|_LOD2]`

- エリア: `A0`〜`A9` か `CM`（共通）。ファイルを分ける（`A1_…` → `a1.glb`、`CM_…` → `common.glb`）。A0 = 序章、A4 = 終章は**仮**
- 種類: 英小文字 2〜8 字。番号: 英数字
- `_front` → 表の層だけ、`_back` → 裏の層だけ、なし → 両方、`_col` → 当たり判定（描かない）
- カスタムプロパティ（extras）: 台座 `materialize_radius`（必須）、共鳴器 `pitch`（必須、例 D4・F#5）、ガラスの置き場所 `placement`
  （near / far / behind-glass）、当たり判定の `layer`（同じ名前の見た目が表と裏の両方にあるときは必須）、`origin`（パイプラインが書く）
- 当たり判定の層: 同じ `<エリア>_<種類>_<番号>` の見た目の層。見た目がなければ両方
- 材質の印（ガラス）: `glass_<種類>[_<役割>]`。種類は `src/core/glass` の8種、役割は scenery / orb / drop / showcase。
  ゲームはこの印から `createGlass` でガラスを作る（分散と薄膜干渉は役割と品質プリセットで決まる）。印のない材質は glTF の値のまま
  読み、分散と薄膜干渉だけを切る
- Blender が重なった名前につける `.001` は誤り（番号を名前の中に入れる）

例（`naming_cases.json`）を Python の検査とゲームの読み取りの両方が読むので、片方だけ変わると両方のテストのどちらかが落ちる。

### 量子化と原点（設計書にない仕組み）

gltf-transform の meshopt は位置を量子化する（KHR_mesh_quantization）。メッシュは [-1, 1] に詰められ、その大きさが節点の拡大率と
位置に入る。そのため:

- 物の位置は形の中心へ動く → 台座の「玉を置く位置」を節点の位置から読めない。パイプラインが書き出しの前に、台座と共鳴器の
  原点を extras の `origin` に書く（台座の原点 = 置いた玉の中心、という作り方の決まり）
- 子を持つ節点では、メッシュが名前のない子の節点へ移る → 名前のない物は、いちばん近い名前つきの祖先の部品として扱う
- 拡大率が 1 でなくなる → glTF の厚み（KHR_materials_volume）は gltf-transform が拡大率で割ってあり、three が掛け直すので、
  印のない透過の材質は glTF の値のままで正しい。印のついたガラスはメートルで厚みを決めるので、`glass.ts` が拡大率で割る
  （安価な遠景のガラスは three が掛けないので割らない）

## 焼き込みを入れない理由と次の手順（受け入れ条件 5）

入れない理由:
- spine で次のスライスと決まっている（S-23 は土台。焼き込みは本番の部屋で意味を持つ）。
- 焼く光は、エリアの時間帯（設計書 光と時間帯: 序章は夜明け前の青、エリア1は朝 …）と本番の造形が決まってからでないと決められない。
  見本の部屋で焼いても、捨てる絵になる。S-24（工房の内装）で、発案者の見た目の判断と一緒に入れるのがよい。
- Cycles の焼きは時間がかかり（泡沫回廊の S-17 では 512px・128spp）、ゲーム側の受け口（lightMap、強さ、色が戻る前後の調整）も要る。

次の手順（S-24 か、その前の焼き込みのスライスで）:
1. 2つ目の UV は、今回の `common/uv.py` が焼き込みと同じ名前 `Lightmap` で作っている。エリアの物を1枚のライトマップに詰めるなら、
   泡沫回廊の `common/bake.py`（0.2.1。すでに写してある）の `bake_lightmaps(objects, out_dir, size, samples)` が、選んだ物をまとめて
   smart project ＋ pack で詰め直して焼く（8bit の sRGB PNG、倍率を extras の `lightmap_scale` に）。
2. `pipeline.py` に焼き込みの段（例 `--bake`）を足す。順は「2つ目の UV → 焼き込み → 書き出し」。焼くのは不透明な物（床・枠・台座）だけ。
   ガラスと当たり判定は除く。
3. 画像の置き場所を決める（判断待ち 5）: 泡沫回廊は glb の外の PNG（extras の `lightmap` が場所）。案1は KTX2 にしたいので、glb に
   埋めて gltf-transform に任せる（色なので ETC1S）か、外に置いて別に変換する。
4. ゲーム側: extras の `lightmap`・`lightmap_scale` を読み、材質の `lightMap`（`channel = 1`）と強さに入れる。色が戻る前後の差は焼き込みでなく
   ゲームの色の調整で（設計書 焼き込み > 時間帯）。
5. 光の模様（コースティクス）: ガラスを通った光を Cycles で床のテクスチャへ。出にくければ真上からの正射影で模様だけを描いて投影する。
6. 反射用の環境画像: エリアの数か所から 360 度のパノラマを Cycles で描き、PMREM でガラスに映す（今の asset-lab は、空と不透明な物を
   その場で PMREM に写している）。

## 判断待ち

1. **KTX-Software の版**: 入っているのは `v5.0.0-rc2~3`（rc 版）で、@gltf-transform/cli 4.5.1 は受け付けて KTX2 にした（gltf-transform が
   求めるのは `ktx` コマンドと 4.4.0 以上。`toktx` は使わない。4.4.x の正式版でも通るはず）。rc 版のままでよいか、正式版に入れ替えるか。
   入れ替えたら `pnpm assets` を走らせ、glb が変わればコミットし直す。
   どのテクスチャをどちらにするか（仮）: 法線と厚みのマップは UASTC（高品質）、色とそのほか（金属・粗さ、AO、発光）は ETC1S（高圧縮）。
   設計書は法線と色しか決めていない。
2. **命名規則を案2と揃えるか**。泡沫回廊の設計書は「命名規則は共通のライブラリにする」と書くが、泡沫回廊は `<部屋>.<部品>[.<番号>]`
   （小文字・点区切り）、案1は設計書の表の `A1_bld_dome03_front`。今は案1の規則を common の外（`blender/scripts/vidro/`）に置き、
   common の `export_glb` に検査を差し替える引数（`check=`）を足した。
3. **命名の仮の決め**: エリア `A0` = 序章、`A4` = 終章、`CM` = 共通。種類は英小文字 2〜8 字。カスタムプロパティの名前
   `materialize_radius`（台座）・`pitch`（共鳴器）・`placement`（ガラスの置き場所）・`layer`（当たり判定）・`origin`（パイプラインが書く）。
   当たり判定の層は同じ名前の見た目の層（なければ両方、表と裏の両方にあれば `layer` が必須）。台座の原点 = 置いた玉の中心。
   印のない透過の材質は、置き場所が near なら警告、far / behind-glass なら止める（Blender とゲームで同じ規則。`naming_cases.json` の `unmarked`）。
4. **ポリゴン数の予算の種別（仮）**: `orb` → 手の玉 8,000、`bld`・`brg` の LOD0 → 近景の建物 40,000、LOD1 以上 → 遠景の建物 5,000、
   ほか（床・枠・台座・街灯…）→ 小物 3,000。超えても止めない（設計書は「目安」）。エリアの合計は詳細度の LOD0 だけを足す。
5. **焼き込みの画像の置き場所**（glb に埋めて KTX2 にするか、泡沫回廊のように外の PNG にするか）。
6. **分散と薄膜干渉**: Blender 5.2 の glTF 書き出しは KHR_materials_dispersion と KHR_materials_iridescence を書ける（glTF Material Output の
   Dispersion、Principled の Thin Film）。設計書の「Blenderから書き出せない設定」は 5.2 では当たらない。ただ、どちらも品質プリセットと
   役割で切り替える（技術設計）ので、印 `glass_<種類>[_<役割>]` を正にし、印のない材質の分散と薄膜干渉は読み込みで切るようにした。
   設計書の文言を直すか。
7. **印のついたガラスの値**: 吸収の色・粗さ・屈折率はライブラリの種類の値（`src/core/glass/kinds.ts`）を使い、Blender の値は使わない。
   厚みは glTF の値（なければ種類の値）、乳白ガラスの内側の灯りは glTF の発光（色×強さ）を使う。Blender で色や粗さを変えたいときは、
   印を外す（glTF の値のままの透過になる）か、種類を足す。値が種類と食い違っても今は警告しない。
8. **meshopt の強さと詳細度の距離（仮）**: meshopt は `medium`（法線を 10 bit で量子化。`high` は 8 bit の八面体で、ガラスの法線の乱れが
   歪みに見えるのを避けた）。THREE.LOD の段の距離 0 / 15 / 40 m。
9. **表の層の当たり判定**（残件の4つ目）と、裏の足場の区画: 1つの `_col` を1区画として S-02 の `BackFooting` に入れた。細かく分ける
   なら作り手が `_col` を分ける（設計書: 裏の足場は細かい区画に分けておき）。
10. **Blender の共通スクリプトの版**: `blender/scripts/common/VERSION` は 0.2.2 の案（泡沫回廊の 0.2.1 に追加だけ）。泡沫回廊へ写し戻すのは親
    （このスライスは泡沫回廊に書き込まない）。`src/core` の版も親が決める（CHANGELOG は「案 0.8.0」）。
11. **並行するセッションの preview サーバー**: 長い全検査の間に、この worktree の `vite preview` が4回、外から止められた（「検査」）。
    ほかのセッションが `vite preview` をポートを限らずに止めていないか。止めるならポート（`SENSOR_PORT` か worktree から決まる値）で限る。
