## 実機の計測（推奨環境）

- 推奨環境の機械は手元にない（発案者）。この Mac で画素数を4倍（`DPR=2`）にした静かな計測で近似し、推奨環境の実機での確認は
  M1 のテストプレイのときに回す（発案者の選択）。
- 参考（推奨環境ではない）: Apple M5 Pro の静かな計測では、中品質の試作部屋と負荷シーンがフレーム p95 2.1ms 以下（process/slices/S-17.md）。

### 近似の計測（2026-10-21、`QUIET=1 DPR=2`、3840×2160 相当、垂直同期なし、Apple M5 Pro、`artifacts/bench-headed-dpr2.md`）

画素数を4倍にすると、画素で決まる重さ（透過、仕上げ、ブルーム）は、4倍遅い GPU で 1080p を描いたときに近くなる。

| 中品質 | WebGPU フレーム平均 / p95 ms | WebGL2 フレーム平均 / p95 ms |
|---|---|---|
| 負荷シーン | 3.05 / 4.0 | 3.90 / 4.7 |
| 試作部屋（最も重い視点） | 3.38 / 4.0 | 3.72 / 4.3 |
| home-dive | 2.89 / 3.8 | 3.83 / 9.8 |

- 判定の目安（p95 が 13.3ms＝60fps の8割以下）に対して、中品質の負荷シーンと試作部屋は約3倍の余裕。推奨環境の GPU がこの Mac より
  4倍以上遅くても、画素で決まる重さなら目安に収まる見込み。高品質でも p95 は 7.4ms 以下。
- 近似で見えないもの: 頂点や描画呼び出しの固定の重さ、CPU（推奨環境はこの Mac より遅い）、Windows と Iris Xe のドライバ、ファンのない
  M1 の熱による低下。これらは M1 のテストプレイで推奨環境の実機を使って確かめる。
- 気になる点: home-dive の WebGL2 は p95 が平均より大きく跳ねる（中 9.8、高 12.8ms）。潜る遷移の途中の一時的な重さとみられる。
  ホーム画面を仕上げる M1 で、跳ねの原因を確かめる。
- 4倍の画素数では、試作部屋の WebGPU が負荷シーンより少し重い（3.38 対 3.05ms）。仕上げ（ブルーム、SMAA）が画素数に比例するため。
