## 目的

S-16 の残件・提案2: ホーム経由では、S-04 の `AudioGate`（ホームの雫の仮の音）と S-16 の試作部屋の音が、同じ「はじめる」でそれぞれ AudioContext を作っていた
（試作部屋の音は pointerdown、AudioGate は click で作るので2つ）。読み込み画面の「はじめる」で1つのエンジンを始め、UI とゲームがそれを使う。

設計書の該当節（`docs/design-snapshot.md`）:
- UI/UX設計 > 画面ごとの設計（読み込み）: クリックで開始（ブラウザは操作があるまで音を鳴らせないため、ここで一度押してもらう）
- サウンドデザイン > 制作方法: 音量は「全体 / 音楽 / 効果音 / 環境音」を別々に調整できる
- リスクと対策（音が自動再生されない）: 読み込み画面で必ず一度クリックしてもらう設計

## 作り

```
読み込み画面の「はじめる」（click / Enter）
  └─ AudioGate.unlock()  … その押下の中で new AudioContext()（ページで1つ）→ AudioEngine.create({ context, 工房, VIDRO_VOLUMES })
        ├─ ホームの雫の仮の音: gate.ping() → engine.startVoice({ bus: 'sfx' })（全体・効果音の音量に従う）
        └─ 試作部屋の音: createPrologueSound(room, { shared: gate }) → gate.whenReady(engine) で受け取り、効果音の系統に Emitter 3つ
直接モード（?direct=1）: AudioGate なし。試作部屋の音が最初の操作で自分のコンテキストとエンジンを作る（S-16 のまま）
home-dive（試作部屋ではない世界）: dive-host が自分の AudioGate を作る（今までどおり）。中身が同じエンジンになっただけ
```

- **持ち主**: ホーム経由ではシーン（`prologue-proto.scene.ts`）が AudioGate を作り、ホーム（dive-host）と試作部屋の音の両方に渡す。片付けは
  「試作部屋の音（Emitter を外す）→ ホーム → AudioGate（エンジンを約20msで絞って切り離し、コンテキストを閉じる）」の順。
  dive-host は渡された AudioGate を片付けない（作った者が片付ける）。渡されなければ自分で作って片付ける（home-dive）。
  押すのは今までどおり読み込み画面の「はじめる」なので、UI の振る舞いは変わらない（エンジンの持ち主の選び方で画面の動きは変わらない）。
- **AudioGate**（`src/ui/audio-gate.ts`）:
  - `unlock()`（押下のハンドラの中で同期に呼ぶ）: 1回目だけコンテキストを作り、その上にエンジンを作る（`AudioEngine.create` は非同期なので一瞬あと）。
    エンジンができたら `bindUnlockGestures(window)`（タブの切り替え等の中断からの再開）と `unlock()`（押下の活性化の中で開始を頼む）。2回目以降（Esc で戻ってもう一度押す）は同じエンジンを再開するだけ。
  - `whenReady(ready)`: エンジンができたら渡す（できていればすぐ）。止める関数を返す。`skip()`（台本）・使えない・片付け後は渡さない。
  - `ping()`: 雫の仮の音（S-04 と同じ正弦波＋非整数倍の倍音）を、エンジンの効果音の系統で鳴らす。押下と同じハンドラの中で鳴らす音（`startOpening` の2音）は、
    エンジンができる一瞬あとに鳴る。押下の前の音は鳴らさず、溜めない。音の節点は、エンジンが鳴り終わるまで持つ声（ScheduledVoice）から参照される（S-09 の決まり）。
  - 状態に `closed` を足した（片付け後）。観測口 `audioGate`（`AudioGateProbe`）: `state`、`contexts`（作った数 0/1）、`uiVoices`（UI が鳴らした数）、
    `voicesStarted` / `voicesDropped`（エンジン全体）、`room`、`volumes`。
- **試作部屋の音**（`src/game/prologue/sound.ts`）: `SoundOptions.shared`（`SharedEngine` = `whenReady` を持つもの。AudioGate がそのまま満たす。game は ui に依存しない）。
  - 共有のときは、操作を待ち受けず、コンテキストもエンジンも作らない。エンジンを受け取ったら Emitter 3つを置く（直接モードと同じ `attach`）。
    開始・中断からの再開・片付けは持ち主に任せ、`dispose` では Emitter を外して待つのをやめるだけ。
  - 受け取ったエンジンの部屋が工房でなければ工房にする（部屋はゲームが決める。S-16 の「部屋の残響は工房」）。今は AudioGate の既定が工房なので何もしない。
  - probe に `shared` を足した。`voicesStarted` / `voicesDropped` は、エンジン全体の数ではなく**この音が鳴らした数**にした（共有のエンジンは UI の音も数えるため）。
    直接モードではエンジンを使うのはこの音だけなので、値は前と同じ。

## 変わった振る舞い（設計書の範囲の中で）

1. **ホーム経由では、音は「はじめる」の押下で始まる**。S-16 では、試作部屋の音が読み込み画面のどこをクリックしても（「はじめる」の前でも）自分のコンテキストを作っていた。
   今は AudioGate だけが作るので、「はじめる」以外のクリックでは何も作らない（設計書「ここで一度押してもらう」のとおり）。e2e で確かめている。
2. **ホームの雫の仮の音がエンジンを通る**（判断待ち1）。前は destination に直接つないでいた（音量の外、残響なし）。今は効果音の系統なので、
   全体の初期値 0.8（利得 0.64、約 -3.9dB）がかかり、効果音の系統の残響への送り（`VIDRO_REVERB_SEND.sfx = 1`）で工房の残響（T60 0.6秒）が少しかかる。
   また、前の AudioGate は状態が `running` になる前に鳴らした音を捨てていた（`context` は running のときだけ返す）ので、作った直後に `running` でなければ
   「はじめる」と同時の2音は鳴らなかった。今はエンジンの開始の猶予（0.25秒、S-09）の中で受け付ける（e2e で押下の音が UI の発音数に数えられることを確かめた）。
3. **ホーム経由の台本（`?autoplay=1`）では、途中でクリックしても鳴らない**。AudioGate は台本のとき作らない（S-04 の `skip()`）ので、試作部屋の音もそれに揃った。
   S-16 の判断待ち5の後半「台本の途中でクリックすると、それ以降の出来事から鳴る」は、直接モードの台本（`?direct=1&autoplay=1`）だけに残る。

## 判断待ち

1. **UI の音を効果音の系統にした**。設計書は音量を「全体 / 音楽 / 効果音 / 環境音」の4つとだけ書き、UI の音がどれに入るかは書いていない。受け入れ条件
   「同じエンジンの4系統の音量に従う」を満たすには4つのどれかに入れる必要があり、雫の音（ガラスの効果音）として効果音にした。結果、ホームでも工房の残響が少しかかる（上の2）。
   ホームの音を乾いたままにしたいなら、(a) ホームの間だけ別の部屋（短い・乾いた）にする（`engine.setRoom`。部屋のデータは `src/audio/rooms.ts`）、
   (b) エンジンに「残響に送らない系統」を足す（`src/core/audio` の変更）、のどちらか。耳での確認（下）で決めたい。
2. **ホーム経由の台本の無音**（上の3）。台本は開発用なので、S-04 の扱いに揃えたままでよいか。途中のクリックで鳴らしたいなら、AudioGate の `skip` を「押下を待たない」だけにして、
   台本の途中の最初の操作で `unlock` する口を足す（dive-host の範囲）。

## 残件

- **設定画面の音量はまだない**（設計書: 設定 > 音、変更は即時反映。M1 の UI）。入口は AudioGate の `engine.setVolume`。このスライスでは「同じエンジンを通る」ことを
  発音数（エンジンの総数 ＝ UI ＋ 試作部屋）とコンテキスト・エンジンの数で確かめた。音量を変えて両方の音が実際に小さくなることを、出力の音で測る e2e はない（音量の口がないため）。
- **世界ごとの空間**: AudioGate のエンジンは工房で始まる（既定）。試作部屋の音は受け取ったエンジンが工房でなければ工房にする。home-dive（仮置きの街と工房）も工房のまま。
  世界が自分の空間を持つなら `DiveWorld`（`src/game/dive-world.ts`、範囲外）に足すのが筋。
- 実機の Chrome の自動再生の警告はセンサーで見えない（S-16 と同じ）。作りで防いでいる: コンテキストは「はじめる」の押下（または直接モードの最初の操作）の中でしか作らない。
  e2e は作った瞬間の `navigator.userActivation.isActive` が真であることを確かめている。
- 2回目以降の中断（タブの切り替え）からの再開は、エンジンの `bindUnlockGestures` 任せ（AudioGate が押下の後に結ぶ）。e2e では確かめていない（S-16 と同じ）。
