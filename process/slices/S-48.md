## 提案（範囲外。統合のときに）

1. `src/game/dive-world.ts` の `DiveWorld` に `applyQuality?(level, preset): void`（S-48: その場の切り替えで世界が受けるもの）を足す。
   今はホームの殻（`dive-host.ts`）が世界の形を見て渡している（`Partial<Pick<QualityScene, 'applyQuality'>>`）。
2. `scripts/lib/preview-server.mjs` の `worktreePort` も、使われていれば次の番号を探す（`playwright.config.ts` の `FIND_FREE` と同じ）。
   ベンチのスクリプトはハッシュ＋ずらしの番号のままで、並行の worktree と重なりうる。
3. AGENTS.md の書き換え・足すもの:
   - 「遊ぶ途中で品質を変えるときは、シーンを作り直さない（S-43）」の後半を次に替える: 品質は URL の `?quality` が勝ち、なければ
     設定の保存（`readSavedQuality`）、なければ自動（S-48: 初回。前に自動が選んだプリセット `readAutoPick` から作り、また測る）。
     `?bench` のときは中で固定（保存を読まず書かない）。プレイヤーの自動は、ゲームの絵を描いている間（`QualityScene.drawsGame`）だけ
     測り、落ち着いたら推奨を覚える（`vidro.autoQuality`）。今その場で変わるのは描画の倍率・動的解像度の範囲・覗く像の倍率・仕上げの
     AA（`PeekPipeline.setQuality`）で、影の大きさとガラスの描き方（分散・遠景の透過）は次に作るときから（`waitsForRebuild`）。
   - **ホームを通る e2e は品質を URL で決める（S-48）。** 決めないと初回の自動が着地の約 10 秒後に測って品質を変える（WebGPU の
     ヘッドレスでは高へ）。自動そのものを確かめる e2e は `autoWindow`・`autoForce` で短く決める（`tests/e2e/S-48-quality.spec.ts`）。
   - **一つのノードを二つの `RenderPipeline` の出力に入れない（S-48）。** ブルーム（`BloomNode`）などは組み立てのたびに `setup` が
     走って内側の材質を作り直すので、出力ごとに組み立てると、使っていなかった方の組み立てが走ったフレームの次にパイプラインを作り直す。
     出力を切り替えたいときは、共有する部分を描画先に描く仕上げと、それを読む仕上げに分ける（`PeekPipeline` の `grade` と `aaPipelines`）。
   - 並列時の注意のポートの文を「ブラウザセンサーのポートは worktree のパスのハッシュの番号から、空いている最初の番号（S-48）。手で
     決めるときは `SENSOR_PORT`」に替える。
