# ループの宣言

このリポジトリの開発は「スライス」を単位に、センサーで確かめながら回すループで進める。
人の判断が要る所（設計の変更、依存の追加、統合、M0ゲートの体感評価）でだけ止まる。

## 目標

M0 技術検証のゲートを通す: **中品質で60fps** と **覗く操作が気持ちいい** を実機で確認できる試作を作る。
スライスの一覧と状態は `process/spine.yaml`。

## 1スライスの流れ（ゲート付き）

```
選ぶ → 受け入れ条件を確かめる → テストを先に書く → 赤を確認 → 実装 → 緑(check.sh --full)
     → 見る(スクリーンショット) → レビュー(新しい目) → 記録の同期 → ブランチにコミット → 報告
```

| ゲート | 通る条件 |
|---|---|
| 赤 | 新しいテストが「未実装」の理由で落ちることを確認し、記録に残した |
| 緑 | `SCENES=<自分のシーン> scripts/check.sh --full` が `ALL OK` |
| 見る | 自分のシーンのスクリーンショットを開いて見た。設計書の数値・柱と食い違いがない |
| レビュー | reviewer の指摘のうち P1/P2 が残っていない |
| 記録 | `process/slices/<ID>.md` に結果の数値・残件・判断待ちを書いた。共通部品を変えたら `src/core/CHANGELOG.md` も |

## 上限と停止条件

- 実装の試行は1スライス累計3回まで（緑にならない実装を捨ててやり直すたびに1回）。
- 見た目の調整は3巡まで。それでも柱に届かなければ、何が足りないかを書いて止める。
- レビューは2巡まで。
- 1セッションで扱うスライスは1つ。終わったら次を自分で始めず、報告して止まる。
- 次のときは作業を止めて発案者に聞く: 設計書に書いていない仕様を決める必要がある / 依存パッケージを足したい /
  自分の `paths` の外を変えたい / 同じ失敗が2回続いた / 性能予算を構造的に守れない。

## 進捗の判定

テストの数や差分の量は進捗に数えない。数えるのは次の3つだけ:
1. センサーが新しく緑になった受け入れ条件
2. スクリーンショットで確認できた、設計書に書かれた見た目や動き
3. 計測値（fps、描画呼び出し、三角形数）の改善

## 失敗をルールに変える

同じ種類の失敗（例: WebGL2経路だけで壊れる、透過の奥のガラスが映らない）が起きたら、
その場で直すだけでなく、テスト・センサーの判定・AGENTS.md の決まりごとのどれかに足して再発を防ぐ。
AGENTS.md の変更は提案として記録し、親が反映する。
